# BASpark 鼠标点击特效迁移讨论稿（v0.1）

## 1. 背景说明

- 当前工作区分为两个部分：
- `fuwari`：主要工作区，个人博客项目（Astro + Tailwind）。
- `BASpark-main`：参考项目，包含鼠标点击特效能力。

本次目标是将 `BASpark-main` 的“鼠标点击特效视觉效果”迁移到 `fuwari` 博客站点中。

## 2. 本次迁移目标

- 在博客网站内呈现点击特效（点击爆裂 + 拖动轨迹）。
- 保持博客交互可用，不影响页面原有点击、滚动、复制按钮等行为。
- 仅在博客前端页面生效，不做系统级全局鼠标监听。

## 3. 从 BASpark-main 拆解出来的可迁移能力

参考实现核心来自：
- `BASpark-main/src/Web/index.html`：`MouseSpark` 画布渲染、点击/移动/抬起事件、粒子/波纹动画。

核心机制（可迁移）：
- Canvas 覆盖层渲染（`pointer-events: none`）。
- 点击触发波纹与粒子爆裂（`boom(x, y)`）。
- 鼠标移动时生成拖尾粒子（按阈值采样）。
- 对象池回收（降低频繁创建对象带来的抖动）。
- 参数化能力：颜色、缩放、透明度、速度、拖尾长度。

## 4. 明确不迁移内容（边界）

以下能力属于桌面程序场景，不属于博客站点迁移范围：
- Windows 全局鼠标 Hook（`MainWindow.xaml.cs`）。
- 托盘、开机自启、注册表配置（`ConfigManager.cs` 等）。
- 隐私弹窗、遥测开关、Windows 通知等桌面应用功能。
- C# 与 WebView 间的 `externalBoom/externalMove` 通信桥接。

结论：我们迁移的是“前端视觉特效引擎”，不是桌面程序外壳。

## 5. 在 fuwari 中的建议落位（讨论方案）

候选注入点：
- `fuwari/src/layouts/Layout.astro`（全站公共布局，最适合挂载一次性前端特效）。

建议策略：
- 新建独立前端特效模块（例如 `src/components/effects/MouseSparkEffect.astro` 或 `src/utils/mouse-spark.ts`）。
- 在布局层初始化，确保页面切换时可复用，不重复挂载监听器。
- Canvas 固定定位覆盖页面，但 `pointer-events: none`，不拦截用户操作。

“仅在博客网站内体现”的落地解释：
- 特效只存在于 `fuwari` 站点前端运行时。
- 不具备系统级、跨应用、跨窗口生效能力。
- 不采集用户隐私数据，仅做本地视觉渲染。

## 6. 可配置项建议（后续可落地到 `src/config.ts`）

建议配置结构（示意）：

```ts
mouseSpark: {
  enable: true,
  color: "45,175,255",
  scale: 1.5,
  opacity: 1.0,
  speed: 1.0,
  maxTrail: 16,
  alwaysTrail: false,
  disableOnMobile: true,
}
```

说明：
- `alwaysTrail`: 不按下鼠标也有拖尾（默认建议关闭）。
- `disableOnMobile`: 移动端默认关闭以节能与避免遮挡触控反馈。

## 7. 性能与可访问性约束

- 遵守 `prefers-reduced-motion`：用户偏好减少动画时自动关闭特效。
- 鼠标移动事件节流（避免高频抖动与耗电）。
- 控制粒子数量与生命周期，避免低端设备掉帧。
- 可通过配置总开关快速关闭。

## 8. 迁移验收标准（讨论版）

- 点击页面内容区域可看到明显且流畅的点击特效。
- 页面按钮、链接、代码复制功能不受影响。
- 页面切换后不出现监听器重复绑定（无明显性能劣化）。
- 在移动端或低性能场景可按策略自动降级/关闭。

## 9. 需要你确认的决策点

请先确认以下 5 点，确认后再进入代码落地：

1. 默认是否开启特效（`enable: true/false`）？默认开启，且不做开关
2. 生效范围是“全站所有页面”还是“仅文章详情页”？全网站所有页面
3. 移动端是否默认关闭？现在我们有移动端吗，有移动端就做，没有就不做
4. 特效颜色是固定值，还是跟随主题色（浅色/深色）动态变化？就按BASpark-main里的来，没有深色和浅色区别
5. 是否需要提供前端开关（例如放在显示设置面板）？不做
