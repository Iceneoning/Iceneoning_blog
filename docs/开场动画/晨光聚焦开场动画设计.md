# 晨光聚焦开场动画设计

> 文档状态：V0.1  
> 目标模块：首页开场动画  
> 方案名称：Morning Focus Intro / 晨光聚焦开场  
> 目标路径：`docs/开场动画/晨光聚焦开场动画设计.md`

---

## 1. 设计目标

本方案用于博客主页首次进入时的开场过渡。

核心情绪不是“浓雾”“梦幻滤镜”或“炫技式 Shader”，而是：

> 喜欢的女孩坐在对面。  
> 世界起初有些灰、有些模糊，随后阳光从窗外照进来。  
> 视线逐渐适应，雾感退去，人物和空间恢复清晰，页面内容随后出现。

视觉重点应当是：

**光把雾切开，而不是雾覆盖整个世界。**

最终画面必须回到清澈、明亮、有空气感的原始主页状态。雾、模糊、低对比度只作为开场阶段存在，不作为长期视觉效果。

---

## 2. 已确认的方向

### 2.1 保留

- 保留当前主页背景图本身的色彩和人物表现。
- 保留已有的轻量背景视差效果。
- 保留当前页面整体布局。
- Navbar、左右侧栏等持久 UI 不应因为开场动画被重新挂载、闪烁、位移或消失。
- 开场结束后，页面回到正常交互状态。

### 2.2 不采用

本轮明确不继续以下方向：

- 不使用 Depth Map 作为核心方案。
- 不使用持续存在的全屏雾气 Shader。
- 不在背景图上长期叠加白色半透明蒙版。
- 不依赖明显的体积光柱。
- 不做强烈 Lens Flare。
- 不做大幅相机推进。
- 不做背景人物明显变形、扭曲或夸张景深。
- 不让“动画效果”比背景人物本身更抢眼。

这些限制的目的，是避免再次出现：

- 人物腿部和皮肤被洗灰；
- 整体像蒙了一层白膜；
- 背景原本的透明感和色彩被破坏；
- 技术效果存在感过强，反而削弱情绪。

---

## 3. 核心体验

整个动画建议控制在约：

`2.4s ~ 2.8s`

理想体验顺序：

```text
灰蓝、轻微失焦
        ↓
视线开始适应
        ↓
暖色阳光进入画面
        ↓
雾感和灰度逐渐退去
        ↓
人物与背景重新清晰
        ↓
主页标题与简介出现
        ↓
轻量 Parallax 接管
        ↓
进入正常主页
```

可以把它理解成一次“视觉对焦”，而不是一次传统网页 Loading 动画。

---

## 4. 动画时序

### Phase A：初始状态

时间：

`0.00s ~ 0.45s`

画面状态：

- 背景已经存在，不使用黑屏。
- 背景亮度略低。
- 对比度略低。
- 饱和度可轻微降低。
- 使用非常轻微的 blur。
- 背景 Scale 稍微放大。
- 主页主体内容暂时不可见。

建议初始参数参考：

```css
filter:
  brightness(0.82)
  contrast(0.90)
  saturate(0.88)
  blur(2px);

transform: scale(1.02);
```

注意：

`blur` 不宜超过约 `2px ~ 3px`。

这里表达的是“刚睁开眼睛时尚未完全聚焦”，而不是浓雾。

---

### Phase B：晨光进入

时间：

`0.35s ~ 1.35s`

从背景光源方向逐渐加入局部暖色光。

推荐使用：

- `radial-gradient`
- 或柔和的大范围伪元素
- 配合 `opacity`
- 必要时配合 `mix-blend-mode`

而不是全屏白色 Overlay。

概念示例：

```css
background:
  radial-gradient(
    ellipse at 70% 15%,
    rgba(255, 236, 196, 0.30) 0%,
    rgba(255, 222, 168, 0.12) 32%,
    rgba(255, 215, 150, 0.04) 48%,
    transparent 68%
  );
```

这里的坐标只是概念值。

正式实现时需要根据当前背景图片实际光源和人物位置调整。

原则：

> 光必须有方向。

不能让整个屏幕同步变白。

---

### Phase C：聚焦

时间：

`0.80s ~ 1.75s`

这是整个开场最重要的一段。

背景逐渐恢复：

```text
低亮度
→ 正常亮度

低对比
→ 正常对比

轻微低饱和
→ 原图色彩

Blur
→ 0

Scale 1.02
→ Scale 1.00
```

推荐缓动：

```css
cubic-bezier(0.22, 1, 0.36, 1)
```

这一阶段要制造：

> “视线终于聚焦到她身上”

的感觉。

不要做明显 Zoom。

Scale 总变化控制在约：

`1.015 ~ 1.025 → 1.0`

即可。

---

### Phase D：UI 出现

时间：

`1.45s ~ 2.25s`

主页内容不要在动画第一帧全部显示。

推荐顺序：

```text
主页标题
   ↓ 80~120ms
简介
   ↓ 80~120ms
其他首页主体元素
```

单个元素采用：

```css
opacity: 0 → 1
translateY(8px ~ 12px) → 0
```

禁止：

- 大范围 Fly In；
- 弹跳；
- 强 Scale；
- 复杂旋转。

主页 UI 的动画只承担“浮现”作用。

---

### Phase E：进入正常状态

时间：

`2.20s ~ 2.80s`

动画结束后：

- 光层进入稳定状态或淡出到极低强度；
- Blur 必须为 0；
- 背景 Filter 恢复正常；
- Scale 恢复 1；
- 主体内容全部可交互；
- 开启鼠标 Parallax；
- 页面进入正常主页状态。

最终状态必须与“不开开场动画时的主页”基本一致。

开场动画不能永久改变背景图片观感。

---

## 5. Parallax 与开场动画的关系

现有轻量视差保留。

但在开场期间：

```text
Parallax = Disabled
```

直到聚焦完成：

```text
Intro Focus Complete
        ↓
Enable Parallax
```

原因：

如果开场阶段同时响应鼠标移动，会导致：

- 聚焦动画和鼠标运动互相干扰；
- Background Transform 来源冲突；
- 画面显得飘；
- 用户难以感知动画设计本身。

建议统一 Background Transform 控制来源。

不要让：

```text
Intro transform
Parallax transform
Hover transform
```

分别直接修改同一个元素的 `transform`。

推荐使用嵌套层：

```text
BackgroundViewport
└── IntroScaleLayer
    └── ParallaxLayer
        └── BackgroundImage
```

或通过统一状态合成 Transform。

## 6. DOM / 图层建议

推荐视觉结构：

```text
HomeBackground
│
├── BackgroundImage
│
├── MorningLightLayer
│
├── AmbientGlowLayer        （可选）
│
└── HomeContent
```

职责：

### BackgroundImage

负责：

- 原始背景图片；
- brightness；
- contrast；
- saturate；
- blur；
- intro scale。

### MorningLightLayer

负责：

- 晨光进入；
- 局部暖色；
- 光源方向。

### AmbientGlowLayer

可选。

只允许非常弱的局部 Glow。

不得成为新的“雾层”。

### HomeContent

负责：

- 标题；
- 简介；
- 首页主要内容；
- UI stagger reveal。

---

## 7. 状态机建议

不要把整个开场散落成大量 `setTimeout`。

建议至少抽象以下状态：

```ts
type IntroState =
  | 'idle'
  | 'focusing'
  | 'revealing'
  | 'completed';
```

流程：

```text
idle
 ↓
focusing
 ↓
revealing
 ↓
completed
```

其中：

### idle

页面刚挂载。

### focusing

背景从灰蓝、轻微失焦过渡到正常状态。

### revealing

主页 UI 进入。

### completed

释放动画状态，并启动 Parallax。

这样后续调节时间轴时，不必修改大量分散逻辑。

---

## 8. 播放规则

完整开场只建议在：

> 本次访问中第一次进入主页

时播放。

站内导航：

```text
文章页 → 首页
小说页 → 首页
其他页面 → 首页
```

不应每次重新播放完整 2.5 秒动画。

否则视觉效果会快速变成操作阻碍。

建议：

```text
首次进入：
播放 Morning Focus Intro

SPA 内再次回到主页：
仅执行现有轻量页面过渡
```

是否采用：

- `sessionStorage`
- 应用级状态
- Router 生命周期状态

由实际项目架构决定。

不建议使用永久 `localStorage` 直接禁止后续播放，因为用户下一次重新访问博客时仍应看到开场。

---

## 9. 与 SPA 导航的边界

开场动画不得改变现有导航架构。

现有页面切换原则继续保持：

> Navbar、左右侧栏等外层 UI 保持稳定，只替换中间内容区域。

因此，开场逻辑应属于：

```text
Home Page / Home Hero
```

而不是：

```text
Global App Mount Animation
```

禁止为了实现开场效果重新挂载整个 App Shell。

否则可能重新引入：

- Navbar 闪烁；
- Sidebar 消失再出现；
- 页面高度瞬时变化；
- 内容区域跳动；
- 路由切换卡顿感。

---

## 10. Reduced Motion

需要兼容：

```css
@media (prefers-reduced-motion: reduce)
```

Reduced Motion 模式下：

- 不进行 Background Scale 动画；
- 不进行 Parallax；
- Blur 动画缩短或取消；
- UI 直接 Fade；
- 总动画控制在约 `150ms ~ 300ms`。

不要完全隐藏内容等待 2.5 秒。

---

## 11. 性能边界

整个方案应优先使用：

- `opacity`
- `transform`
- CSS gradient

需要谨慎使用：

- `filter: blur()`
- `backdrop-filter`
- 大面积动态 `box-shadow`

尤其背景为高分辨率大图时，大范围 Blur 可能增加 GPU 合成压力。

因此：

```text
Blur 小
持续时间短
只发生在 Intro
```

禁止引入：

- Canvas 粒子系统；
- WebGL；
- Three.js；
- 实时 Depth Map；
- 大规模 Shader；

除非以后有明确的新视觉需求。

当前方案完全没有必要使用这些技术。

## 13. 验收标准

### AC-01 最终背景不能变灰

动画结束后：

- 人物肤色；
- 腿部；
- 头发；
- 背景主体；

不得相比原图明显灰白。

---

### AC-02 不存在永久雾层

动画完成后不能存在：

```text
全屏半透明白层
持续 Blur
持续低 Contrast
持续低 Saturation
```

---

### AC-03 晨光具有明确方向

用户应能感觉到：

> 光从某个方向进入。

而不是整个屏幕同时亮起来。

---

### AC-04 聚焦感成立

动画应能明确感知：

```text
轻微失焦
→
恢复清晰
```

但不能产生明显视力模糊或晕动。

---

### AC-05 原 Parallax 保留

开场完成后，现有背景视差行为恢复。

---

### AC-06 SPA Shell 不被破坏

站内切换页面时：

- Navbar 不重新闪烁；
- 左右侧栏不因开场动画消失；
- 主布局不重新 Mount；
- 只影响主页对应视觉层。

---

### AC-07 重复进入首页不重新播放完整开场

同一 SPA Session 内第二次返回主页时，不应重新等待约 2.5 秒。

---

### AC-08 移动端正常

移动设备：

- 不依赖鼠标；
- Parallax 可关闭；
- 背景最终状态与桌面端一致；
- 不出现滚动条抖动。

---

### AC-09 Reduced Motion 可用

启用 `prefers-reduced-motion` 后：

- 页面立即可用；
- 不执行明显缩放和视差运动。

## 15. 后续调试顺序

实际实现后，视觉调试必须按照以下顺序：

```text
1. 先关闭所有附加效果
2. 只调 Background 初始灰度
3. 调聚焦恢复
4. 调晨光方向
5. 调晨光强度
6. 调 UI 出现时机
7. 最后恢复 Parallax
```

如果画面再次出现“灰、脏、蒙”的问题：

第一优先检查：

```text
Overlay Alpha
Filter Saturation
Filter Brightness
Blend Mode
```

而不是继续增加新的光效或雾效。

## 16. 核心设计原则

整个方案最终只需要记住一句话：

> 雾是开始，阳光才是最终状态。

开场动画不是给主页增加一层特效。

它的作用是：

> 用两秒多的时间，把用户从页面外面带进当前背景所表达的那个世界。

## 18. V0.2 图形学重构记录

状态：

`Implemented / Awaiting Visual Review`

### 18.1 V0.1 失败原因

V0.1 的核心表现仍然是：

```text
隐藏首页内容
+
CSS Filter
+
CSS Gradient
+
延迟 Fade In
```

虽然 technically 属于动画，但没有真正的动态视觉事件。

结果就是：

- 用户第一感受不是“进入一个场景”，而是“页面晚了一点才出来”；
- `1450ms` 后才开始显示中心内容，直接放大了加载等待感；
- 晨光只是静态 Gradient 的 opacity 变化，没有流动、散射、粒子或空间运动；
- 没有充分使用 GPU shader / particle 等图形学能力。

因此 V0.1 不再作为目标实现，只保留为失败实验记录。

### 18.2 V0.2 架构

V0.2 将真正的视觉事件迁移到 WebGL2：

```text
Home Intro Lifecycle
        │
        ├── requestAnimationFrame Timeline
        │
        ├── Fullscreen Triangle
        │       └── Procedural Sunlight Fragment Shader
        │
        └── GPU Point Particle Batch
                ├── Static Seed Buffer
                ├── Vertex Shader Motion
                └── Fragment Shader Soft Dust
```

新增：

```text
src/scripts/home-intro-renderer.ts
```

职责分离为：

```text
home-intro.ts
    → Session / Swup / Timeline / Reduced Motion

home-intro-renderer.ts
    → WebGL2 / Shader / Particle / Blend / Render Budget
```

### 18.3 程序化晨光

晨光不再由 CSS Radial Gradient 主导。

V0.2 使用一个 Fullscreen Triangle，仅三个顶点覆盖整个屏幕。

Fragment Shader 内部计算：

- 三组不同宽度和方向的光束；
- 光源附近的 Source Glow；
- 两档 Value Noise；
- 随时间移动的低频扰动；
- Intro Progress 控制的出现 / 衰减 Envelope。

因此晨光本身具有：

```text
方向
+
流动
+
密度变化
+
时间变化
```

而不是一张固定的半透明渐变图。

### 18.4 GPU 粒子系统

V0.2 Desktop 默认：

```text
180 Particles
```

小屏 / Coarse Pointer：

```text
96 Particles
```

每个粒子 CPU 只上传四个随机 Seed：

```text
x / lateral / depth-size / phase
```

每帧不在 JavaScript 中逐粒子修改位置。

Vertex Shader 根据：

- Seed；
- Time；
- 光束方向；
- 横向 Corridor；
- Sin Drift；
- 不同速度层；

实时计算粒子位置。

Fragment Shader 使用：

```glsl
gl_PointCoord
```

计算圆形 Soft Falloff 与 Core Glow。

最终形成：

> 阳光照进空气后可见的漂浮尘埃。

粒子 RGB 使用 Additive Blend，以光点方式叠加，而不是用灰白 Alpha 覆盖背景。

### 18.5 Draw Call 边界

V0.2 每帧主要只有两次 Draw Call：

```text
1 × Fullscreen Triangle
1 × Particle Batch
```

不创建：

- 每粒子 DOM；
- 每粒子 Canvas；
- 每粒子独立 Draw Call。

### 18.6 Timeline 修正

总时间：

```text
3200ms
```

但 UI 不再等待完整动画。

首页内容 Reveal 提前到约：

```text
620ms
```

流程调整为：

```text
0ms
背景已经存在
WebGL 第一帧立即开始

0 ~ 600ms
晨光形成

约 320 ~ 900ms
尘埃进入可见区

约 620ms
中心 UI 开始 Reveal

约 1.4s
UI 已基本可读

1.4 ~ 2.5s
晨光 + 粒子继续作为环境动画存在

2.5 ~ 3.2s
光场与粒子退出

3.2s
Parallax 恢复
```

因此动画长度可以是 3.2 秒，但页面不会“等 3.2 秒才加载完成”。

### 18.7 性能边界

V0.2 使用：

- `requestAnimationFrame`；
- WebGL2；
- 单 Canvas；
- 单静态 Particle Seed Buffer；
- Desktop 180 / Compact 96 粒子；
- DPR 上限 `1.25`；
- 总渲染像素预算约 `1.35M`；
- 两个主要 Draw Call；
- Intro 完成后停止 RAF；
- Reduced Motion 不启动 Canvas 动画。

WebGL2 不可用时：

> Intro 生命周期仍可继续，页面只退化为轻量 CSS Focus / Reveal，不阻塞页面。

### 18.9 下一步视觉验收

V0.2 后续原则发生变化：

不再问：

> CSS 光层够不够亮？

而要观察：

- 光束是否真的像“阳光照进来”；
- 粒子是否像空气尘埃，而不是星星；
- 粒子密度是否过高；
- 光束方向是否符合背景构图；
- 动画是否从第一帧就让人明确知道“正在发生一个场景过渡”；
- UI 在约 620ms 开始出现是否足够快；
- 背景人物是否仍保持原画颜色与高光。

后续只围绕：

```text
Shader 参数
Particle 参数
Timeline 参数
```

进行视觉调优。

不再回退到“隐藏内容 + 等待 + Fade In”作为主要过场。
