# 首页“启航”区块响应式布局故障复盘

## 1. 问题摘要

首页“启航”区块在窄桌面视口下出现严重的纵向拉伸：首篇文章封面占据大部分卡片宽度，标题、日期和摘要只剩下很窄的一列，中文被逐字换行，卡片高度接近整页。

该问题从约 `1024px` 的桌面断点开始出现，并会延续到更宽的视口。移动端和较窄的平板宽度没有触发同样的双栏组合，因此表现相对正常。

## 2. 用户可见现象

- “崭新出炉”文章卡片中的正文区域被压缩到约 `48px`。
- 标题实际可用宽度只有约 `16px`，只能显示单个汉字宽度。
- 摘要按单字纵向排列，将卡片高度拉伸到约 `984px`。
- 右侧“精彩回顾”顶部内容正常，但其下方出现大面积无意义空白。
- 页面没有产生横向滚动条，因此常规的 `overflow-x` 检查无法发现该问题。

## 3. 根因

问题由两层布局在同一个视口断点下独立切换造成：

1. `MainGridLayout.astro` 在 `lg` 断点将页面切换为“左侧栏 + 主内容”布局，主内容可用宽度随之明显缩小。
2. 首页区块又在 `lg` 断点使用固定的 `18rem + 1fr` 双栏布局。
3. 双栏中的首篇文章卡片在 `sm` 断点以后采用横向排列，封面固定占用 `15rem`。
4. 在复现视口 `1052 × 900` 下，首篇文章卡片总宽度为 `288px`；扣除 `240px` 封面后，正文只剩 `48px`，再扣除内边距后标题可用宽度仅为 `16px`。

根本原因是首页子布局依据“整个视口宽度”响应，而它真正需要依据的是“主内容容器的可用宽度”。视口已经达到 `lg` 并不代表嵌套在侧栏旁边的内容也足够宽。

## 4. 修复方案

首页“启航”区块改用 CSS Container Queries：

- 区块默认保持单列。
- 当区块自身内容宽度达到 `36rem` 时，首篇文章卡片才切换为横向图文布局。
- 当区块自身内容宽度达到 `49rem` 时，才切换为“首篇文章 + 精彩回顾”双栏。
- 双栏使用带有可读性下限的 `minmax()`：首篇文章最少 `30rem`，回顾列表最少 `17rem`。

这样，页面侧栏是否出现不再直接决定首页卡片的内部布局。组件只在自身确实有足够空间时增加列数。

## 5. 验证标准

在常见视口宽度下检查以下项目：

| 视口宽度 | 预期布局 | 关键要求 |
| --- | --- | --- |
| `390px` | 单列、封面在上 | 无横向溢出，标题和摘要正常换行 |
| `640px` | 单列、首篇图文横排 | 正文保持可读宽度 |
| `1024px` | 单列、首篇图文横排 | 不因左侧栏出现而压缩成逐字竖排 |
| `1052px` | 单列、首篇图文横排 | 截图中的故障不再出现 |
| `1280px` | 单列、首篇图文横排 | 三栏外层布局下仍保持可读 |
| `1440px` 及以上 | 双列 | 两侧均达到设定的最小宽度 |

所有视口还应满足：

- 文档宽度不超过视口宽度。
- 标题可用宽度明显大于单个汉字。
- 首页导航区块高度由实际内容决定，不出现接近整页的异常拉伸。
- `pnpm check` 和 `pnpm build` 均成功。

## 6. 后续防回归原则

- 嵌套组件的列数应依据组件容器宽度，而不是机械复用页面视口断点。
- 固定宽度媒体与弹性正文横排时，必须为正文保留明确的最小可读空间。
- 响应式回归不能只检查横向滚动条，还要记录关键元素的宽度和高度。
- 新增侧栏、目录栏或修改 `--page-width` 后，应重新执行本页的视口矩阵检查。
