# 小说分区技术设计与页面布局方案

> 项目：冰霓の梦之旅 / Fuwari 魔改版  
> 目标：在现有博客之外增加独立的“小说”内容体系，同时保持统一视觉语言。  
> 设计关键词：沉浸、轻阅读、章节连续性、角色感、蓝白通透、少干扰。

## 1. 产品定位

小说不建议直接当普通 Blog Post 的一个 `category`。

普通博客的阅读模型是：

```text
首页发现 → 点开单篇文章 → 阅读 → 返回
```

小说的阅读模型是：

```text
小说馆 → 选择作品 → 查看作品详情 → 选择章节 → 连续阅读 → 上一章 / 下一章
```

两者信息架构不同。

因此推荐把小说做成独立内容集合和独立路由，而不是把所有章节塞进现有文章目录。

推荐 URL：

```text
/novels/                         小说馆
/novels/yaoxing/                 《瑶幸》作品页
/novels/yaoxing/001/             第一章
/novels/yaoxing/002/             第二章
```

第一版不必引入过深层级。即使以后有“卷”，也可以先将卷信息作为章节元数据，而不是立即加入第四层路由。

## 2. 推荐内容模型

建议在 `src/content/` 下新增：

```text
src/content/
├─ posts/
├─ spec/
└─ novels/
   └─ yaoxing/
      ├─ index.md
      ├─ 001.md
      ├─ 002.md
      └─ 003.md
```

职责：

- `index.md`：作品元信息；
- `001.md`：第一章；
- `002.md`：第二章；
- 后续按数字追加。

### 2.1 作品 Frontmatter

```yaml
---
type: novel
novelId: yaoxing
title: 瑶幸
subtitle: 风会记住她走过的地方
description: 一名能够看见精灵的少女，自十三岁开始独自周游世界。
author: 冰霓
status: 连载中
cover: /images/novels/yaoxing/cover.webp
hero: /images/novels/yaoxing/hero.webp
accentHue: 205
started: 2026-09-14
tags: [奇幻, 旅行, 精灵]
---
```

### 2.2 章节 Frontmatter

```yaml
---
type: chapter
title: 风从窗边吹进来
novel: yaoxing
chapterId: "001"
order: 1
chapter: 1
volume: 1
volumeTitle: 风从城里吹来
published: 2026-09-14
description: 瑶幸故事的开端。
draft: false
---
```

`order` 是作品内唯一、稳定的正整数，用于目录和上一章 / 下一章排序；`chapter` 与 `volume` 只负责显示章号、卷号。`chapterId` 与文件名和 URL 保持一致，例如 `001.md`、`chapterId: "001"`、`/001/`。

## 3. Astro 内容集合设计

第一版只增加一个 `novels` collection，并用判别联合按 `type` 区分：

```ts
z.discriminatedUnion("type", [novelSchema, chapterSchema])
```

这是对当前项目侵入最小的方案。

建议支持字段：

```text
type
novel
novelId
title
subtitle
description
author
status
cover
hero
accentHue
started
chapterId
order
chapter
volume
volumeTitle
published
updated
draft
tags
lang
```

以后小说数量明显增加，再考虑拆成 `novelSeries` 与 `novelChapters` 两个 collection。

## 4. 页面与组件架构

建议新增页面：

```text
src/pages/novels/index.astro
src/pages/novels/[novel].astro
src/pages/novels/[novel]/[chapter].astro
```

建议新增组件：

```text
src/components/novel/NovelCard.astro
src/components/novel/NovelHero.astro
src/components/novel/NovelChapterList.astro
src/components/novel/NovelReader.astro
```

第一版先控制在四个组件以内，避免小说系统刚开始就再次积累大量抽象层。

## 5. 导航入口

Navbar 建议新增：

```ts
{
  name: "小说",
  url: "/novels/",
}
```

建议顺序：

```text
启航 | 介绍 | 目录 | 小说 | 杂谈 | 代码 | 友之屋
```

“小说”属于一级内容，不建议藏在归档筛选里。

## 6. 小说馆 `/novels/`

设计目标：不像“文章列表”，而像作品陈列馆。

### 6.1 首屏

```text
┌──────────────────────────────────────────────────┐
│  NOVEL LIBRARY                                   │
│  小说馆                                           │
│  在故事里走得慢一点。                             │
│                                                  │
│  [ 当前连载 01 ]  [ 已完结 00 ]  [ 总章节 12 ]   │
└──────────────────────────────────────────────────┘
```

视觉建议：

- 继续使用当前 `card-base` 毛玻璃体系；
- 背景继续透出 `site-bg.webp`；
- 顶部使用很轻的 `var(--primary)` radial glow；
- `NOVEL LIBRARY` 用小字号 + 较大字距；
- 中文标题 2rem～2.5rem；
- 不重新启用旧 Banner 系统。

### 6.2 作品卡

桌面建议左右结构：

```text
┌──────────────┬────────────────────────────────────┐
│              │  连载中 · 奇幻 / 旅行              │
│    COVER     │                                    │
│              │  瑶幸                              │
│              │  风会记住她走过的地方              │
│              │                                    │
│              │  一名能够看见精灵的少女……          │
│              │                                    │
│              │  12 章节   最近更新 09.14           │
│              │                         [开始阅读 →]│
└──────────────┴────────────────────────────────────┘
```

移动端变为上下：

```text
[ 封面 ]
瑶幸
副标题
简介
状态 / 章节数
[开始阅读]
```

不要做传统小说站那种密集小字链接列表。

## 7. 单部作品页 `/novels/yaoxing/`

这是小说分区最重要的“作品主页”。

### 7.1 Hero

推荐两栏：

```text
┌─────────────────────────────────────────────────────┐
│ ┌──────────────┐   瑶幸                             │
│ │              │   风会记住她走过的地方             │
│ │    COVER     │                                    │
│ │              │   连载中 · 奇幻 · 旅行 · 精灵      │
│ │              │                                    │
│ └──────────────┘   一名能够看见精灵的少女……          │
│                                                    │
│                    [ 从第一章开始 ] [ 继续阅读 ]     │
└─────────────────────────────────────────────────────┘
```

建议：

- 封面比例 3:4 或 4:5；
- 圆角沿用 `--radius-large`；
- 状态用一个小 Badge；
- 可将 `hero.webp` 作为极弱背景，透明度控制在 0.10～0.18；
- 背景图不能影响正文对比度。

### 7.2 作品简介

Hero 下方单独一张轻卡：

```text
关于这个故事

正文简介……
```

可以增加“舞台 / 风格 / 主角 / 状态”等少量信息，但不要把作品页做成世界观百科。

### 7.3 章节列表

推荐：

```text
第一卷 · 风从城里吹来

01  风从窗边吹进来                 2026.09.14
02  她第一次叫出了精灵的名字       2026.09.18
03  河边的下午                     2026.09.22
```

交互：

- 整行可点击；
- Hover 轻微右移 2～4px；
- 最新章节右侧显示 `NEW`；
- 已读章节可降低标题明度；
- 每章只使用浅分隔线，不使用厚边框。

移动端可以隐藏日期，或者把日期移动到标题下方第二行。

## 8. 阅读页 `/novels/yaoxing/001/`

阅读页不要直接复用普通博客文章页的信息结构。

博客文章页里的分类、Tag、License、侧栏、技术元数据，对小说阅读会形成干扰。

小说阅读页建议单独使用 `NovelReader`。

### 8.1 正文宽度

推荐：

```text
max-width: 46rem ~ 50rem
```

中文小说正文每行太长会显著降低阅读体验。

### 8.2 顶部信息

```text
瑶幸
第一卷

第一章
风从窗边吹进来

2026.09.14
```

其中“瑶幸”链接回作品主页。

不要显示：

- category；
- tags 大列表；
- GitHub 风格元数据；
- 字数卡片；
- 大型 License 卡片。

### 8.3 正文排版

推荐起点：

```css
font-size: 1.05rem;
line-height: 2;
letter-spacing: 0.015em;
```

段落间距建议：

```text
1.25em ~ 1.5em
```

正文颜色不要纯黑 / 纯白：

```text
light: black / 78% ~ 82%
dark:  white / 78% ~ 84%
```

这样会比技术文章更柔和。

### 8.4 场景分隔

小说常见：

```text
***
```

可以渲染为：

```text
        ✦   ✦   ✦
```

不要使用粗重 `<hr>`。

## 9. 阅读导航

正文末尾：

```text
┌──────────────────┐        ┌──────────────────┐
│ ← 上一章          │        │ 下一章 →          │
│ 河边的下午        │        │ 第一次出远门      │
└──────────────────┘        └──────────────────┘

                [ 返回目录 ]
```

移动端改成上下两个大按钮。

上一章 / 下一章必须根据作品内唯一的 `order` 自动排序生成，不要手写 URL。

## 10. 阅读进度

第一版建议只使用 `localStorage`。

Key 示例（带数据版本，便于以后迁移）：

```text
fuwari:novel:yaoxing:progress:v1
```

第一版采用“连续阅读进度”：打开某一章后，将它以及排序在它之前的章节视为已读。

```json
{
  "version": 1,
  "lastReadSlug": "006",
  "readThroughOrder": 6,
  "updatedAt": "2026-09-14T12:00:00.000Z"
}
```

用途：

- 作品页显示“继续阅读”；
- 章节列表显示已读状态；
- 下一阶段再考虑恢复滚动位置。

不建议第一版就同步到服务端。

## 11. 阅读进度条

建议页面顶端增加 2px 的细进度条：

```text
height: 2px
background: var(--primary)
```

不显示百分比数字。

它应该固定在顶部，但层级不要压过 Navbar。

## 12. 阅读模式

第一版不要增加复杂阅读器设置。

当前博客已经有：

- Light / Dark；
- 主题色。

小说分区直接复用即可。

以后确实有需求，再增加：

```text
紧凑 / 标准 / 宽松
```

三档行距，而不是再做一套完整设置面板。

## 13. 视觉语言

小说分区应和博客属于同一站点，但 UI 更安静。

博客页面：

```text
信息密度：中
UI 存在感：中
功能元素：多
```

小说页面：

```text
信息密度：低
UI 存在感：低
内容存在感：高
```

继续复用：

- `card-base`
- `var(--primary)`
- `--radius-large`
- Light / Dark
- 当前毛玻璃背景

减少：

- 图标数量；
- 彩色 Badge；
- 元数据行；
- Sidebar 小组件；
- 大幅 Hover 动画。

## 15. 与当前布局的关系

不建议让小说阅读页直接使用现有 `MainGridLayout` 的三栏形态。

推荐关系：

```text
NovelLibrary / NovelDetail
    ↓
Layout.astro
    ↓
Navbar + Background + Theme
    ↓
独立小说内容容器
```

阅读页：

```text
NovelReaderLayout
    ↓
Layout.astro
    ↓
Navbar
    ↓
单列正文
```

这样可以复用站点壳，同时避开博客 SideBar / TOC 对小说阅读的干扰。

## 16. 推荐实现阶段

### Phase 1：内容模型

- 新增 `novels` collection；
- 定义作品 / 章节 Frontmatter；
- 建立 1 部测试小说与 2～3 个测试章节。

### Phase 2：小说馆与作品页

- `/novels/`；
- `/novels/[novel]/`；
- `NovelCard`；
- `NovelHero`；
- `NovelChapterList`。

### Phase 3：阅读页

- `/novels/[novel]/[chapter]/`；
- `NovelReader`；
- 上一章 / 下一章；
- 返回目录。

### Phase 4：阅读体验

- 阅读进度条；
- `localStorage` 最后阅读章节；
- “继续阅读”；
- 已读章节状态。

### Phase 5：视觉细化

- 手机端；
- 暗色主题；
- Hero 背景；
- 空状态；
- 完结状态；
- 多作品布局。

## 17. 第一版明确不做

为了避免小说功能再次变成新的冗余来源，第一版不要做：

- 用户账号；
- 云端阅读进度；
- 评论；
- 点赞；
- 书签系统；
- 字体商店；
- 复杂阅读器控制面板；
- 数据库；
- 服务端渲染依赖；
- 小说与博客共用同一个 archive 筛选器。

全部保持纯静态 Astro 内容即可。

## 18. 最终建议

小说分区的核心原则是：

> 技术上复用博客基础设施，信息架构上与 Blog Post 分离，视觉上减少 UI 干扰。

对于当前项目，最合适的第一版不是“做一个大型小说站”，而是做一个精致、独立、可连续阅读的静态小说馆。

如果以《瑶幸》作为第一部作品，建议优先把作品页和阅读页做得足够好，再考虑多作品筛选、搜索和额外功能。
