# 小说区视觉重构与字体规范

> 当前版本：V0.2 / Visual V3.1

## 1. 当前结论

Visual V1、Visual V2 与 Visual V2.1 均作为探索过程保留历史意义，但不再作为当前视觉基线。

Visual V3 的核心原则是：

> 小说区特殊的是内容布局，不是独立 UI 皮肤。

小说馆、作品页和阅读页继续使用 Fuwari 本身的圆角、毛玻璃、主题色、按钮和背景关系，只在少量深蓝表面上增加冷白微光标题，建立小说区的幻想感。

## 2. 为什么调整

前两轮实际页面验证暴露出一个共同问题：虽然单个元素并不一定难看，但组合后与博客本体产生割裂。

主要表现为：

- 楷体、书刊英文、几何编号等元素形成了另一套视觉语言；
- `VOL.01 / CH.01`、轨道圆与悬浮工具轨让小说区更像独立阅读器；
- 小说页面为了“高级感”增加过多装饰，反而削弱 Fuwari 原本的蓝白动漫博客气质；
- 用户实际观感为“不一定说得出具体原因，但整体很丑、很不搭”。

因此 Visual V3 不再继续增加设计语言，而是做减法。

## 3. Visual V3 关键词

```text
Fuwari 原生
蓝白
毛玻璃
动漫背景
冷白微光
少量幻想感
低噪音
阅读优先
```

明确废弃：

```text
楷体大标题
复古书刊排版
大号英文诗句
技术编号式 VOL / CH
大面积几何轨道装饰
常驻悬浮阅读工具轨
独立于博客的小说 UI 皮肤
```

## 4. 发光标题规范

参考用户提供的其他博客标题效果，Visual V3 保留“冷白微光字”，但只用于深蓝或偏暗的局部 Hero。

推荐效果：

```css
color: rgba(255, 255, 255, 0.96);
text-shadow:
    0 0 4px rgba(255, 255, 255, 0.56),
    0 0 12px rgba(140, 210, 255, 0.34),
    0 0 28px rgba(77, 158, 235, 0.20);
```

约束：

1. 正文不发光。
2. 普通浅色卡片中的标题不发光。
3. 发光只承担层次与幻想感，不做强霓虹。
4. 不使用多层高饱和蓝色外发光。

## 5. 小说馆

小说馆 Hero 回归单一 Fuwari 卡片结构。

视觉结构：

```text
NOVEL

小说馆
在故事里走得慢一点，让风景多停留一会。

1 部作品 · 3 个章节 · 1 部连载
```

Hero 使用半透明深蓝覆盖，让站点背景仍能参与视觉；“小说馆”使用冷白微光。

不再显示：

- `01` 编号方块；
- `FICTION / ARCHIVE`；
- 十字线；
- 巨型几何圆环。

### 5.1 小说馆 Showcase 主视觉

小说馆 Hero 右侧保留约三成宽度作为作品主视觉区域。

每部小说可以在作品 `index.md` 中配置：

```yaml
showcase:
  image: /novels/yaoxing/showcase.webp
  position: 72% center
  scale: 1
```

字段职责：

- `image`：小说馆右侧使用的透明立绘或横向插画；
- `position`：控制人物/主体在 Showcase 中的构图位置；
- `scale`：处理不同立绘尺寸差异，允许范围为 `0.5 ~ 2`。

图片选择优先级：

```text
showcase.image
→ hero
→ cover
→ 无素材 fallback
```

当前《瑶幸》已经配置正式 `showcase.webp`；后续其他作品若尚无主视觉，则继续使用低权重 fallback，不拿站点背景或无关图片冒充作品立绘。

当只有一部小说时，Showcase 静态显示该作品。

当有两部及以上作品时：

- 默认每 10 秒 Cross Fade 到下一部；
- Cross Fade 时长约 760ms；
- 用户 Hover 某部作品卡时立即切换到对应作品；
- 键盘 Focus 作品卡时同样切换；
- 鼠标/焦点离开后恢复自动轮播；
- `prefers-reduced-motion` 下关闭自动轮播与过渡动画。

移动端和平板窄屏隐藏 Showcase，不为了展示立绘压缩正文信息。

## 6. 作品卡

作品卡直接回到 Fuwari 卡片家族。

保留：

- 封面；
- 作品名；
- 副标题；
- 简介；
- 状态；
- 标签；
- 章节数；
- 最近更新时间；
- 开始阅读。

不再通过左侧蓝线、技术编号、几何背景等方式制造独立视觉。

作品名使用普通现代无衬线黑色标题，不发光。

## 7. 作品详情 Hero

作品详情页允许使用深蓝覆盖层，因为这是适合冷白微光的主要场景。

作品名与副标题可以使用轻微冷白微光。

封面与阅读按钮继续保持 Fuwari 常规圆角与按钮语义。

## 8. 阅读页

阅读页继续保持单列正文与两侧留白，但外层阅读卡稍微扩大，避免宽屏下显得过瘦。

桌面端：

```text
阅读卡外层：56rem
实际正文：最大 50rem
```

因此卡片整体更有存在感，但中文正文行长不会无限增加。

章节头部继续使用自然中文信息，不显示 `VOL / CH / CHAPTER` 技术编号。

阅读工具不再固定显示在标题下方，也不恢复传统侧栏。

### 8.1 底部感应式阅读工具栏

桌面端正常阅读时工具栏完全隐藏。

当鼠标进入视口底部约 `120px` 的感应范围时，工具栏从底部中央淡入并轻微上浮：

```text
0%   目录   A−   A+   行距   顶部
```

交互规则：

- 进入底部感应区：立即显示；
- 鼠标离开：延迟约 560ms 隐藏，防止操作按钮时闪退；
- 鼠标停留在工具栏上：保持显示；
- 工具栏隐藏时不建立透明覆盖层，不拦截正文底部点击；
- 键盘 Focus 工具栏时保持显示；
- 触屏设备没有 Hover，因此工具栏改为章节正文后的静态可见工具组。

字号与行距仍复用 `fuwari:novel:reader-settings:v1` 持久化设置。

## 9. 页面宽度

小说馆与作品页：

```css
width: min(100%, 76rem);
```

章节阅读页：

```css
.novel-reader-wrap {
    width: min(100%, 56rem);
}

.novel-reader-body {
    max-width: 50rem;
    margin-inline: auto;
}
```

取消侧栏不代表正文铺满页面；扩大的是阅读卡外壳，不是无限拉长正文。

## 10. Swup 与 Navbar

Navbar 继续位于 Swup `#page-layout` 外，保持稳定。

博客主体与小说主体通过 `#page-layout` 完整交换，左右侧栏随博客主体一起淡出，不在小说页残留。

## 11. 字体职责

UI、小说馆、作品名、章节标题继续使用博客当前现代无衬线字体栈。

只有小说正文使用：

```css
"Noto Serif SC",
"Source Han Serif SC",
"Songti SC",
"STSong",
"SimSun",
serif
```

不额外引入大型中文 WebFont。

## 12. 全站主题控制兼容性

小说区不得绕开全站主题系统。

Visual V3 的深色 Hero 必须从 `--primary` 派生，而不是写死固定蓝色；Light / Dark 模式分别使用主题色与深色基底混合得到对应背景。

Navbar 位于 Swup `#page-layout` 外，因此调色板按钮需要在首次加载、Swup 启用和后续 `page:view` 后保持事件绑定。Layout 在每次 `page:view` 后重新执行 `loadTheme()` 与 `loadHue()`，确保持久化 Navbar 与新页面样式始终同步。

这意味着：

- 选择“浅灰 / 明亮紫 / 湛蓝”后，小说 Hero 与全站主题一起变化；
- Light / Dark 切换会重新作用到页面与小说 Hero；
- 页面通过 Swup 切换后不应出现控件失效或主题状态不同步。

## 13. 移动端

- 小说馆 Hero 与作品卡继续复用全站移动端卡片处理；
- 阅读设置允许自动换行；
- 不出现悬浮工具轨；
- 正文不贴边；
- 发光效果保持轻量，不牺牲文字清晰度。

## 14. 维护边界

1. 后续小说视觉首先复用全站现有组件语言。
2. 新效果必须先回答“它是否与博客本体一致”。
3. 发光只用于深色 Hero 的少量主标题。
4. 不恢复常驻传统侧栏；底部阅读工具栏只能按需感应显示，不长期占据阅读界面。
5. 阅读正文与展示 UI 的字体职责继续分离。
6. 审美调整必须根据实际页面截图复核。

## 16. 瑶幸当前正式视觉资源配置

当前资源目录：

```text
public/novels/yaoxing/
├─ cover.webp
├─ hero.webp
└─ showcase.webp
```

作品 Frontmatter 已配置：

```yaml
cover: /novels/yaoxing/cover.webp
hero: /novels/yaoxing/hero.webp
showcase:
  image: /novels/yaoxing/showcase.webp
  position: 72% center
  scale: 1
```

职责固定为：

- `cover.webp`：作品卡与作品详情封面；
- `hero.webp`：作品详情页横向背景主视觉；
- `showcase.webp`：小说馆右侧作品轮播/联动立绘；
- `showcase.position` 与 `showcase.scale` 仅负责适配不同作品立绘构图，不写死在组件代码中。

`hero.webp` 自身已经包含完整插画和标题设计，因此页面层只以半透明主题遮罩将其作为氛围背景使用，避免与前景标题、简介和阅读按钮争夺可读性。

后续纯视觉实验统一记录到全站级 `docs/美化方案/`，当前小说馆 Hero 光影过渡方案以该目录中的文档为准。
