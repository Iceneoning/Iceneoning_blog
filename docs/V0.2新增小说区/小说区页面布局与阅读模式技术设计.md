# 小说区页面布局与阅读模式技术设计

## 1. 文档目的

本文用于明确博客小说区在 V0.2 阶段的页面结构、阅读模式、布局边界与复用策略。

当前目标不是直接实现完整小说系统，而是先固定小说馆、作品页、阅读页三类页面的整体布局规则，避免后续开发时继续沿用现有博客正文页的左右侧栏结构，导致阅读区域过窄、视觉重心分散。

## 2. 设计目标

小说区需要同时满足以下目标：

1. 继续复用博客已有的全站视觉体系，不单独做成一个完全割裂的新站点。
2. 小说馆、作品页、阅读页都不再直接套用当前博客正文页的左右侧栏结构。
3. 阅读页优先保证长文本阅读体验，减少目录、信息卡片、侧栏等元素对正文的持续干扰。
4. 在宽屏下获得更大的整体视觉面积，但正文行宽仍需要受控，不能横向铺满屏幕。
5. 保留后续扩展空间，例如章节目录、作品信息、阅读进度、字体字号控制、夜间阅读、移动端适配等。

## 3. 总体布局策略

小说区继续复用以下全站能力：

- 全站 Navbar
- 全局背景
- 主题系统
- Light / Dark 模式
- 全局字体与基础样式
- 全站响应式断点

但小说区主体不再直接依赖当前博客文章页的主布局结构。

建议新增一套独立小说布局：

```text
Layout.astro
└─ NovelLayout / NovelReaderLayout
   ├─ Navbar
   ├─ Novel Main Area
   └─ Footer / Global Layer
```

其中：

- `NovelLayout`：用于小说馆与作品详情页。
- `NovelReaderLayout`：用于章节阅读页。

两者都属于现有网站内部布局，而不是独立站点。

## 4. 小说馆页面

小说馆是小说区入口，目标是展示作品，而不是提供文章式阅读。

页面不使用博客文章页的左右侧栏。

推荐结构：

```text
Navbar

小说馆 Header
- 标题
- 简介
- 可选筛选 / 分类

作品展示区域
- 作品卡片
- 封面
- 标题
- 简介
- 状态
- 标签

Footer
```

小说馆主体可以使用比博客正文页更宽的容器，例如约：

```css
max-width: 1200px ~ 1400px;
```

具体值后续根据卡片尺寸与视觉效果调整。

小说馆不需要强制控制在阅读正文的窄宽度，因为这里属于内容浏览页。

## 5. 作品页

作品页负责展示单部小说的整体信息。

建议结构：

```text
Navbar

作品 Hero
- 封面
- 作品名
- 简介
- 作者 / 状态 / 标签
- 开始阅读按钮

作品介绍

章节目录

可选附加信息
- 更新时间
- 字数
- 世界观说明
- 备注

Footer
```

作品页依然不使用博客文章页的固定左右侧栏。

桌面端可以允许“封面 + 信息”横向布局，但章节目录应回归单列或宽主栏布局。

## 6. 阅读页核心方案

阅读页是小说区最重要的页面。

其核心原则是：

> 页面整体区域可以宽，但正文阅读列必须窄。

因此不要把“取消侧栏”理解成“正文铺满屏幕”。

推荐结构：

```text
Navbar

NovelReaderLayout
└─ Reader Main
   ├─ 章节标题
   ├─ 章节元信息
   ├─ 正文
   └─ 上一章 / 目录 / 下一章

Footer / Bottom Navigation
```

桌面端页面整体容器可以扩大，例如：

```css
.reader-shell {
    width: min(100%, 1200px);
    margin: 0 auto;
}
```

正文实际阅读列保持在约：

```css
.reader-content {
    max-width: 46rem;
    margin: 0 auto;
}
```

根据字体与视觉测试，可以在 `46rem ~ 50rem` 之间调整。

这样既能避免原有双侧栏压缩小说正文，也不会让一行文字在超宽屏上变得过长。

## 7. 为什么不继续使用左右侧栏

当前博客布局更适合文章、博客、知识类页面。

左右侧栏通常承担目录、作者信息、标签、推荐内容和页面导航。这些内容对博客文章很有价值，但对连续小说阅读会产生额外视觉干扰。

小说阅读的主要行为是：

```text
进入章节
→ 连续阅读
→ 翻页
→ 继续下一章
```

因此阅读页应把注意力集中在正文，而不是长期占用横向空间展示辅助信息。

章节目录等功能可以改为顶部入口、底部入口、抽屉、浮层或移动端弹层，而不是常驻左右侧栏。

## 8. 阅读页宽度与排版原则

### 8.1 正文宽度

目标为 `46rem ~ 50rem`，优先从 `46rem` 开始测试。

正文不能直接继承一个 1000px 以上的超宽容器。

### 8.2 字号

桌面端建议正文基础字号在 `17px ~ 19px` 之间测试，移动端建议为 `16px ~ 18px`。

### 8.3 行高

小说正文行高建议明显高于普通 UI 文本：

```css
line-height: 1.8 ~ 2.0;
```

### 8.4 段落间距

中文小说不应直接照搬英文博客的段落节奏。

建议重点测试首行缩进、段间距、对话段落、空行与分隔符，并在后续确定统一正文 Markdown 书写规范。

## 9. 阅读导航

章节末尾建议提供固定的三段式导航：

```text
上一章    目录    下一章
```

桌面端可以水平排列。移动端可以根据空间调整布局，但仍应保证目录入口清晰可达。

阅读页顶部也可以保留轻量返回路径：

```text
小说馆 / 作品名 / 当前章节
```

但不建议使用过重的 Breadcrumb 视觉样式。

## 10. 移动端策略

移动端小说阅读不需要侧栏。

正文容器直接使用：

```css
width: 100%;
padding-inline: 1rem ~ 1.25rem;
```

重点保证正文不贴边、字号足够、行高舒适、导航按钮容易点击、章节标题不会过度占屏。

## 11. 与当前博客系统的关系

小说区不是重写现有博客 Layout。

推荐关系：

```text
现有博客页面
→ 继续使用 MainGridLayout 等现有布局

小说馆 / 作品页
→ NovelLayout

章节阅读页
→ NovelReaderLayout
```

这样可以让两套内容类型并存，而不是为了小说区破坏当前博客页面结构。

## 12. 后续可扩展项

本阶段暂不要求全部实现，但布局层需要为以下功能保留空间：

- 字体大小切换
- 行距切换
- 阅读主题切换
- 阅读进度
- 自动记录上次阅读章节
- 章节目录抽屉
- 键盘翻页
- 上一章 / 下一章快捷键
- 移动端底部工具栏
- 章节字数
- 更新时间
- 连载 / 完结状态

这些功能不应在第一版全部堆进 UI。

优先级仍然是：

```text
可读性
> 页面结构稳定
> 导航清晰
> 功能数量
```

## 13. 当前阶段结论

V0.2 小说区采用独立布局体系。

最终方向确定为：

1. 小说馆、作品页和阅读页不再沿用博客正文的左右侧栏结构。
2. 全站 Navbar、背景、主题系统继续复用。
3. 小说馆和作品页使用较宽的 `NovelLayout`。
4. 阅读页使用独立单列 `NovelReaderLayout`。
5. 阅读页外层可以更宽，但正文控制在约 `46rem ~ 50rem`。
6. 章节目录等辅助功能不常驻侧栏，优先采用页面内入口、抽屉或浮层。
7. 不为了小说区重构现有博客文章页面。

该方案作为后续小说区页面实现的布局基线。
