# 小说馆 Hero 光影过渡方案

> 状态：Visual V3.2.2 当前实施方案

## 1. 目标

小说馆 Hero 使用：

```text
左信息
+
中过光
+
右展示
```

解决此前两个主要问题：

1. 左侧文字与右侧立绘之间出现明显空洞；
2. Showcase 像一块单独贴进去的矩形面板，颜色边界突兀。

本方案不与《瑶幸》的“风”“精灵”等主题绑定，后续任何小说都可以继续使用。

## 2. 左侧信息区

继续保留：

- 小说馆
- 简介
- 作品 / 章节 / 连载统计

左侧是信息锚点，不叠加复杂装饰。

## 3. 中间光影过渡区

中段不放新的文本或 Logo。

采用可见的六层通用视觉：

- 中央 Bloom 光场；
- 主/副柔光流；
- Lens Flare 核心与横向光 streak；
- 双轨道椭圆弧光；
- 棱镜碎片；
- 多点微光粒子。

截图复核后要求这些效果在正常桌面亮度下必须明确可见，不能只存在于 CSS 数值中。V3.2 与 V3.2.1 的实际截图均显示光影不足，因此 V3.2.2 将光影层从 Showcase 下方提升到 Showcase 上方，同时增加 Lens Flare、双弧光和更多粒子。

原实现中 Showcase 左侧叠加的深色渐变会形成明确竖直色差，V3.2.1 已取消该深色过渡，改为对 Showcase 整体使用宽范围 Alpha Mask。

### 3.1 主层：柔光流

两条低透明度的斜向柔光带从中段向右流动。

职责：

- 连接左文字与右侧 Showcase；
- 消除中间“什么都没有”的断层；
- 形成轻微体积光感。

### 3.2 辅层：棱镜碎片

使用少量半透明几何碎片。

要求：

- 数量少；
- 尺寸小；
- 不形成新的 UI 图标；
- 透明度明显低于主标题和角色立绘；
- 只负责制造层次与微弱科技/幻想感。

### 3.3 点缀：微光粒子

使用极少量冷白粒子与主题色 Bloom。

不形成星空，不铺满 Hero。

## 4. 右侧 Showcase

Showcase 仍然由小说 Frontmatter 数据驱动。

右侧不再显示：

- 小说标题 Caption；
- 副标题 Caption；
- NOVEL 标识；
- 其他重复文字。

Showcase 只承担作品主视觉。

## 5. Showcase 与 Hero 的融合

Showcase 不再表现成 Hero 内部的独立矩形区域。

实现规则：

- Showcase 覆盖 Hero 完整高度；
- 右边贴 Hero 边界；
- 左侧使用 Alpha Mask 渐隐；
- Hero 与人物之间增加明确但克制的主题色 Bloom 与弧光；
- 角色图片不建立独立底板；
- 不出现上、下、左三条明显矩形边界。

Mask 大致分布：

```text
0%       14%        34%        54%        100%
透明  →  很淡   →   半显   →   完整   →   完整
```

## 6. 动效

允许：

- 柔光带 8~11 秒非常缓慢漂移；
- 几何碎片 9~14 秒小范围漂浮；
- 粒子 4~5 秒轻微呼吸；
- Showcase 多作品继续使用已有 Cross Fade。

禁止：

- 快速扫光；
- 大幅旋转；
- 高频粒子；
- 强烈霓虹闪烁；
- 会分散阅读注意力的循环动画。

`prefers-reduced-motion` 下关闭新增光影动画。

## 7. 响应式

桌面宽屏：

```text
左侧信息约 52%
中段光影自然跨越
右侧 Showcase 约 46%
```

小于约 1050px 时适度缩小 Showcase。

小于 900px：

- Showcase 隐藏；
- 光影过渡层隐藏；
- Hero 回到单列 Fuwari 卡片，避免移动端视觉拥挤。

## 8. 维护边界

1. 光影层必须是通用小说馆视觉，不读取作品主题关键词。
2. 角色作品差异只由 Showcase 图片表达。
3. 不在中过渡区增加文本。
4. 不恢复右侧作品 Caption。
5. 后续若增加独立装饰素材，应放在共享小说资源目录，而不是某部小说目录。
6. 美化首先解决层次与融合问题，不以“装饰数量”作为目标。
