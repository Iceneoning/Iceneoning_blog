# 全站图形学视觉层美化方案

> 版本：Lightweight Visual Layer V1  
> 状态：Fog/WebGL 已移除，回归低侵入视觉增强  
> 适用范围：首页、文章页、目录页、介绍页等全站公共布局；小说馆继续保留自身专用 Hero 图形系统。

## 1. 方向

当前博客的基础 UI 已经完成，不再通过继续堆卡片、圆角、渐变或复杂组件来“美化”。

本轮目标是：

> 保留现有 Fuwari 信息架构与蓝白科技感，通过 GPU / Shader、2.5D 深度、光照与微弱后处理增加空间感和生命感。

视觉语言保持：

- 蓝白科技感；
- 编辑式排版；
- 少量游戏 UI / BA 气质的几何信息感；
- 动效克制，阅读优先；
- 图形学效果作为 Visual Layer，而不是重新设计业务 UI。

## 2. 不可破坏的交互合同

当前结构是正式基线：

```text
Navbar          常驻
Left Sidebar    常驻
Right Sidebar   常驻

#swup-container
└─ 仅替换中间内容
```

全站美化必须遵守：

1. 不把 Navbar、左右侧栏移入 Swup 容器；
2. 不改变 `astro.config.mjs` 中 `containers: ["#swup-container"]` 的局部替换语义；
3. 全站 Graphics Layer 同样位于 Swup 容器外，切页时实例常驻；
4. 图形层不得参与正文排版，不得造成 Layout Shift；
5. 继续遵守“最小修改，不借机重构”的原则。

## 3. 全站渲染分层

```text
Background Image
        ↓
2.5D Background Parallax
        ↓
Frosted / Theme Overlay
        ↓
Persistent WebGL Graphics Layer
  ├─ Ambient Light
  └─ Film Grain
        ↓
Persistent UI
  ├─ Navbar
  ├─ Left Sidebar
  └─ Right Sidebar
        ↓
#swup-container
  └─ Main Content
```

## 4. Visual V1：当前实现

### 4.1 Background Parallax

背景图根据 Pointer 位置产生极小反向位移：

```text
X：约 ±8px
Y：约 ±5px
```

特点：

- UI 完全不移动；
- 只有背景图移动；
- 使用插值产生轻微惯性；
- 现有 `backgroundConfig.scale = 1.08` 继续作为露底安全区；
- 小屏、粗指针和 reduced-motion 下关闭。

这是轻量 2.5D Screen-space Parallax，不是传统 POM / Parallax Occlusion Mapping。

### 4.2 GPU Ambient Light

全站新增单个透明 WebGL2 Canvas。

Fragment Shader 负责：

- 宽范围柔和主题色环境光；
- 极慢漂移；
- Pointer 只提供少量光场偏移；
- 不形成明显的“鼠标手电筒”；
- Light / Dark Mode 跟随当前 `--primary`；
- 使用透明 Premultiplied Alpha 与原背景合成。

目标不是让用户直接看到“一个特效”，而是让页面不再像静态截图。

### 4.3 Film Grain

同一 Fragment Shader 加入极弱程序化噪声：

- 约 12Hz 更新；
- 不使用额外纹理；
- 不形成明显颗粒；
- 主要打散半透明卡片与背景过于平滑的数字塑料感。

视觉权重必须低于 Ambient Light。

## 5. Visual V2：第二阶段增量

### 5.1 Ambient Light 可感知度调整

Visual V1 的 Ambient Light 在当前背景图、Frosted Overlay 和深色半透明卡片组合下过于隐蔽。

V2 对 Ambient Light 做过多轮可见度调优。V2.4 当前实现不再依赖 Canvas 整体 opacity 或 `soft-light`，而是在 Fragment Shader 内直接控制 Ambient Alpha；浅色主题约 0.030，深色主题约 0.050，并与 Misty Fog 一起使用 Premultiplied Alpha 合成。

目标仍然是：能感到背景存在缓慢环境变化，但看不到明确的圆形 Spotlight。

### 5.2 Procedural Grid

V2 最初在 Fragment Shader 内尝试程序化网格；当前正式实现使用独立的 CSS Technical Grid Overlay，避免与背景 Fog Shader 耦合。

实现特征：

- 使用 `fract / fwidth / smoothstep` 生成抗锯齿网格线；
- 不加载 PNG / SVG 网格贴图；
- 初始网格密度为 `28 × 18`；根据首轮肉眼反馈调整为更易辨识的 `24 × 15`，让单格略大；
- 通过 Screen Edge Mask 只让网格在屏幕外围逐渐显现；
- 页面中心主动衰减，避免文章正文区域变成 HUD；
- 网格交点比普通线条略亮；首轮因过淡难以辨认，V2.1 已提高线宽、外围覆盖范围和主题色混合强度，但仍限制在背景外围。

它的职责是提供轻微几何秩序感，而不是制造明显“赛博背景”。

V2.2 实际页面复核发现：Shader Grid 位于 `site-content` 下方时会被大面积卡片视觉上盖住。最终保留 `#site-technical-grid` 作为独立外围 Overlay：使用 CSS `linear-gradient + radial-gradient + mask-image` 程序化生成网格和交点，不使用图片；该层位于 UI 上方但只在屏幕外围显现，中央正文区域完全衰减。后续清理时已删除底层 Shader Grid，只保留这一套可见实现。

### 5.3 Mouse Edge Light

普通 `.card-base` 在鼠标经过时获得局部蓝白边缘高光。

实现方式：

- Pointer 事件找到当前最近的 `.card-base`；
- 根据 `getBoundingClientRect()` 计算鼠标在卡片内的局部坐标；
- 复用单个 `.site-card-edge-light` Overlay，在卡片之间移动；
- Overlay 使用 `radial-gradient + mask-composite`，只保留约 1px 的边缘区域；
- 不给每个 Card 创建 Canvas；
- 小说馆 Hero / Novel Hero / Novel Reader 已有独立图形系统，V2 主动排除这些视觉中心。

静态复核发现 DateTimePanel、ArchiveCard、NovelCard 等组件已经使用自身 `::after`。因此 V2 最终没有占用全局 `card-base::after`，而是改用独立 Overlay 子元素，避免破坏既有装饰层。

### 5.4 Card Hierarchy / Glass Depth

V2.4 开始不再把所有 `.card-base` 当成同一种材质，而是建立三级视觉层级：

- Level 1：主内容卡。用于首页导航、文章卡、正文页等视觉中心；背景更稳定，Blur / Saturation / 阴影更明确；
- Level 2：Profile / DateTime 等持续辅助信息；透明度、边框与阴影均低于主内容；
- Level 3：Categories / Tags 等辅助 Widget；背景更轻，减少和正文争抢视觉重量；
- `glass-inset`：用于主卡内部的精选内容等“卡中卡”，进一步降低外阴影，避免层层白盒。

浅色主题主要通过背景透明度、Blur、Saturation、亮边与冷色阴影区分深度；深色主题对应调整为更低亮度的半透明深色玻璃和更克制的阴影。

目标不是让用户识别出“三种卡片样式”，而是让视觉重心自然落在中间内容区。V2.6 根据连续肉眼反馈确认：主内容卡约 0.84 Alpha 会把背景 Fog 基本遮掉，因此改为“更透明 + 更高 Blur”的真正玻璃策略。浅色 Primary / Secondary / Tertiary 调整到约 0.74 / 0.54 / 0.38，并提高 Blur，让背景雾可以透过玻璃形成柔和色彩层次，同时保持文字区域稳定。

### 5.5 Misty Fog Shader

V2.4 将 WebGL 背景从单一 Ambient Light 扩展为低频迷雾柔光场。

实现方式：

- 继续复用现有单个 WebGL2 Fullscreen Triangle；
- 使用 2D Value Noise + 3 Octave FBM 生成大尺度雾场；
- 两组 FBM 以不同方向、极低速度漂移；
- 使用第一层噪声做轻微 Domain Warp，避免出现规则云块；
- 不生成线、光带、粒子或任何可被识别为独立物体的主特效；
- Fog 与 Ambient Light 使用透明 Premultiplied Alpha 合成，背景插画始终保留；
- V2.6 不再只提高单层 Fog Alpha，而是拆成 Far / Near 两层密度场，分别经过近似 Beer-Lambert 的散射响应后前向合成；浅色 Near Fog 峰值约 0.118、Far Fog 约 0.082，深色对应约 0.155 / 0.110；
- Grain 只轻微扰动 Alpha，避免纯数字渐变感。

设计目标是“页面整体有柔雾和呼吸感”，而不是“这里有一个 Shader 特效”。V2.6 的关键不是让背景空白处更亮，而是让 Fog 能通过半透明高 Blur 玻璃影响卡片内部色调，从而参与整个页面，而不只存在于卡片缝隙。

### 5.6 Typography / Spacing / Layout Composition（已回退）

V2.7 曾尝试放大 Typography / Spacing 差异，但最终画面偏离目标截图。当前已按“崭新出炉 / 精彩回顾”改版后的页面作为布局边界，恢复文章卡、侧栏、元信息和首页导航区的旧版字号与间距；三栏、DateTimePanel、Swup 局部切页以及首页精选/回顾功能保留。

以下内容仅保留为实验记录：

本轮调整：

- 主栅格 gap 从 16px 提高到 20px，文章卡之间由 16px 提高到 20px；
- 首页导航区 padding 从 16px 提高到 20~24px，并增加模块内部纵向节奏；
- 首页精选标题提高一档，同时将“崭新出炉 / 精彩回顾”弱化为更小、更疏的 Eyebrow Label；
- 文章卡标题改为更稳定的 Display 层级：约 1.65rem / 1.85rem，配合负 Tracking 与更紧凑行高；
- 元信息统一压到约 0.8rem，并降低颜色权重，使日期 / 分类 / 标签退到辅助层；
- 摘要正文改为约 0.98rem、7 级行高，提升阅读节奏；
- Profile 标题与简介减重；Categories / Tags 标题由粗体 18px 调整为更轻的 16px；
- Widget 内边距从 16px 提高到 20px，增强左右栏呼吸感。

Fog 不再继续通过“提高 Alpha”解决可见度。V2.8 改为修正合成层级：SiteGraphicsLayer 从背景层迁入 `#site-content` stacking context，但仍位于主 UI 的 `z-30 / z-50` 下方，使 `backdrop-filter` 能把 Fog 当作真正的卡片 backdrop 采样。

同时在 Shader 中新增两组大尺度各向异性 Soft Scattering Light：不形成可识别光球，而是被 Fog Density 调制的柔亮区域。

### 5.7 Atmospheric Fog V1

在实际视觉复核与外部实现对照后，背景 Shader 不再追求“低 Alpha 蓝色蒙层”。当前版本改成：

- 低频 FBM + Domain Warp 生成大尺度雾团；
- Base / Detail / Breakup 三组密度共同决定轮廓；
- 使用屏幕高度形成轻微 Height Fog，下方更厚、上方更通透；
- Fog 同时拥有暗部吸收、主题蓝中间调和蓝白受光区，因此有真实明暗差，而不是整屏泛蓝；
- 两组宽尺度 Soft Scattering Light 只负责照亮雾密度，不形成独立光球或光带；
- Dark Mode Fog Alpha 上限约 0.285，Light Mode 约 0.190，受光雾另有低强度散射项；
- 继续使用 Premultiplied Alpha，并保持单 WebGL2 Context、约 30 FPS、像素预算限制。

目标是：即使不依赖卡片本身，背景空白区域也能明确看到缓慢移动的雾密度和柔光层次。

V2 根据网页案例进一步修正“雾的运动语言”：参考全屏程序化 Fog 常见的高纵向采样尺度、持续上升、FBM + Domain Warp 结构，把原先的大块缓慢色云替换为两层不同速度的 Rising Mist Sheet。主层约使用 `X 2.45 / Y 4.55` 的采样比例，辅层约 `X 1.72 / Y 3.25`，再通过 Breakup / Veil 侵蚀形成雾丝和远处薄雾。若 V2 仍无法满足真实体积感，下一档不再继续改 2D 参数，而改用低步数 Raymarching + 3D Noise 的真正 Volumetric Fog。

### 5.8 Volumetric Fog V1

Atmospheric Fog V2 仍然属于屏幕空间二维密度层，无法稳定产生真正的空间厚度。V1 因此更换渲染模型：

- 每个像素沿视线执行固定 `10-step ray march`；
- 密度来自程序化 3D Value Noise + 2-Octave FBM，而不是 2D 雾纹；
- 每一步按 Beer-Lambert `T = exp(-sigma_t * ds)` 计算局部透射；
- 使用前向积分累计 transmittance 与 single in-scattering；
- 两个宽尺度体积光源只影响雾内散射，不单独画光斑；
- 体积前后边缘使用 depth fade，避免看到矩形 volume slab；
- Theme 只负责雾的 shadow / mid / light 色相，不再决定雾是否存在。

性能边界同步调整：像素预算约 `760k`，动态刷新约 `24 FPS`。低分辨率本身也会帮助体积雾保持柔和，不需要 Retina 原生分辨率。

V1.1 根据实际截图先把雾色从主题蓝改为高 albedo 的中性灰白，并尝试宽尺度体积光束与前向散射。

V1.2 根据进一步肉眼反馈确认：用户需要的是“整体柔光从雾体内部透出来”，而不是“柔光打在迷雾上”。因此移除可读成局部光束的 Soft Beam / HG 主导逻辑，改为 `Diffuse Backlight Field + Multiple-Scattering Compensation`。

V1.3 根据实际截图确认 V1.2 仍存在“闪光弹 / 白云”问题。根因不是单纯雾色太白，而是 Canvas 使用 `premultipliedAlpha: true` 时，V1.2 的 `volumeColor` 可因 scatterEnergy > 1 明显高于最终 `volumeAlpha`，浏览器会把它合成为低 Alpha、高 RGB 的近似自发光层。V1.3 将散射限制为 energy-bounded albedo，降低浅色雾亮部与 extinction，并把积分结果先恢复成 straight fog color，再按最终 Alpha 重新预乘；同时增加 `RGB <= Alpha` 的非自发光保险约束。浅色 volume alpha 上限约 `0.23`，避免再次出现白云式过曝。

V1.4 根据“雾太弱”的反馈只增强 Density / Coverage：降低 3D density 的 smoothstep 阈值、扩大 Z 方向 depth coverage、提高 density 总量约 12%，并将浅色 extinction 从约 `0.76` 提到 `0.94`、volume alpha 上限从 `0.23` 提到 `0.31`。V1.3 的 energy-bounded scattering、雾色和 premultiplied-alpha 合成保持不变，因此增强的是“雾量”，不是“白色亮度”。

V1.5 根据“雾已经明显，但不够阳光”的对比图进行调优：保持 V1.4 的 Density / Coverage，不再加雾；新增 `Broad Sunlight Field`，用超宽域暖色日照提高受光雾的 inscattering，并将受光水汽从灰白推向暖白。

V1.6 根据“依然没感觉”的反馈提高宽域日照，但实际截图仍暴露出一个更根本的问题：normal alpha 合成会让灰白雾直接覆盖背景，高亮皮肤/衣物也会被压灰。

V1.7 改用 `screen` 后虽然不会把高光直接压暗，但实际肉眼仍有轻微灰/褪色感。原因是 Screen 会让所有通道持续向亮侧移动，中性灰白雾会把彩色中间调一起洗淡。

V1.8 浅色主题改为 `mix-blend-mode: lighten`：逐通道只保留 backdrop/source 中较亮的值。这样已经很亮的皮肤、白衣、白色背景不会被较暗的雾源改变，而较暗背景仍能被雾抬亮。浅色 Canvas opacity 调到约 `0.84`，但同步降低 neutral fog / light / sun 色值与 Sun Wash，避免因更高 opacity 再次洗白。深色主题仍保留 Screen。体积密度、Beer-Lambert、energy-bounded scattering 与 premultiplied-alpha 修复保持不变。

### 5.9 Fog / Volumetric Shader 结论

经过 Atmospheric Fog V1~V2 与 Volumetric Fog V1~V1.8 多轮实现和肉眼复核，最终决定删除全屏 Fog/WebGL Shader。核心原因不是 Shader 无法工作，而是它会持续改写背景插画的高光、肤色和局部构图；这张背景本身已经承担主要视觉叙事，全屏参与介质对它的收益低于代价。

当前全站保留：Background Pointer Parallax、Mouse Edge Light、外围 Technical Grid。后续视觉增强优先采用局部、可控、不会覆盖整张背景图的效果。

## 6. 后续候选

### 6.1 Depth Map Parallax

后续可为背景图准备灰度 Depth Map：

```text
白色 = 近
黑色 = 远
```

由 Shader 按深度偏移纹理采样 UV，形成更真实的 2.5D 层次。

需要单独处理：

- 深度贴图制作；
- 边缘露底；
- 不同背景图的兼容；
- 性能与移动端降级。

### 6.2 Screen-space Refraction

仅考虑用于少量视觉 Anchor：

- Profile；
- 首页精选区域；
- DateTime Panel。

边界：

- 折射偏移约 1~2px；
- 不给所有 Card 使用；
- 不做液态玻璃或果冻式形变。

## 7. 不采用的方向

全站不采用：

- 高频粒子雨；
- 星空背景；
- 大面积霓虹 Bloom；
- 长期 Chromatic Aberration；
- 鼠标拖尾作为主视觉；
- 全站 Liquid Glass；
- 每张 Card 一个 Canvas / WebGL Context；
- 为本轮特效引入 Three.js / PixiJS；
- 会持续抢夺文章注意力的大幅循环动画。

现有 Mouse Spark 继续作为独立交互特效，不与背景 Graphics Layer 合并。

## 9. 性能预算

Visual V2.4 约束：

- 单个 WebGL2 Context；
- Fullscreen Triangle，无 Mesh / Scene / Camera 框架；
- 不开启 MSAA；
- Volumetric Fog 每像素固定 10-step ray march + 程序化 3D noise，渲染像素预算约 76 万像素；
- DPR 最大 1.25，并按总像素预算继续降采样；
- Shader 动态刷新约 24 FPS；
- Tab 不可见时停止 RAF；
- 小于 900px 或粗指针设备隐藏全屏 Canvas；
- `prefers-reduced-motion` 下停止动态视差，Shader 只保留静态一帧；
- WebGL2 不可用时自动退化，不影响 HTML/CSS 页面；
- Mouse Edge Light 全站只复用一个 Overlay，不创建 per-card Canvas 或常驻子节点。

## 10. 视觉权重

```text
Background Parallax   ███████    空间深度
Misty Fog Field       █████      环境基底
Ambient Light         ████       柔光辅助
Mouse Edge Light      ███        局部交互
Technical Grid        ██         外围辅助
Film Grain            █          极弱
```

原则：

> 不再设置独立“主特效”；所有动态只服务整体空间层次与材质感。

V2.4 以 Parallax 提供深度，以 Misty Fog / Ambient 提供环境氛围；Mouse Edge Light 仅承担局部交互反馈，Grid 与 Grain 保持低权重。

## 11. 验收标准

工程：

- `pnpm check` 通过；
- `pnpm build` 通过；
- Swup 切页不重复创建 Canvas；
- Navbar / 左右 Sidebar 不刷新、不消失、不移动；
- reduced-motion 正常降级；
- 移动端不承担全屏 Shader 成本。

视觉：

- 能感觉到背景具有轻微深度；
- 环境光不形成明显圆斑；
- Film Grain 必须靠近观察才容易察觉；
- 不降低正文可读性；
- 最终以实际页面截图与交互复核为准。
