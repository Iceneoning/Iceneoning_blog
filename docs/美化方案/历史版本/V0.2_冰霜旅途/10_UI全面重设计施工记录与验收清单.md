## 1. 为什么进行了第二轮大幅重做

第一轮虽然实现了小型信标、SVG 航线、三层卡片透明度，但原模板的文章大卡、头像大卡、分栏形态和导航都没有真正改变，用户验收后指出“还是看得出来是模板”。本轮确认：只换材质和装饰不等于 UI 重设计。

重新确立本版实际视觉表达为 **Personal Atlas / 航行手记**：不是把标准博客卡片包装成旅行，而是将首页改为编辑式封面与记录版式，文章列表由卡片堆栈转为编号索引，周边功能成为辅助路标。保留原始背景插画与主题变量。

## 3. 特别保留的行为合同

- Navbar、左侧作者/目录、右侧时间面板不进入 `#swup-container`，普通博客站内换页仍只替换中心。
- 进入/离开独立小说布局保留 `data-no-swup` 边界。
- Light/Dark/Hue token 继续从现有主题系统派生；不替换背景图片，不新增 Fog、Depth Map、全屏 WebGL。
- 类别与标签仍有可点击链接；归档筛选仍使用原数据属性与原 JS 协议。
- 时间/运势面板的数据逻辑不变；未更改文章/小说 Markdown、Frontmatter 与站点设置。
- 动画需求仍按 08 设计单独施工，先验收静态样式。

## 6. 用户验收路径

在仓库目录运行 `pnpm dev`，依次查看：

1. 首页是否**明显**不再是白色卡片堆栈：大幅封面、最新一站与编号手记的层级是否清楚。
2. 1440px / 1052px / 390px 视口：顶部不拥挤、正文标题正常换行、内容不横向溢出。
3. 导航从首页→文章→归档→分类/标签→介绍→友之屋→小说馆/阅读页：栏目指示、内容替换、稳定侧栏与主题不闪烁。
4. 普通文章中的标签、目录、图片/Lightbox、上/下篇；小说章节和底部阅读栏不受影响。
5. Light/Dark/Hue：主题切换正常，人物背景颜色没有变灰，文字对比足够。
6. 如果静态版审美仍不足：优先修改构图、卡片密度和排版，不急于加雾、Shader 或粒子来掩盖布局问题。

最终静态样式只有在用户实机截图与交互验收合格后，才可以标记为 ACCEPTED。

## 8. 用户第二批截图：比例与可观察动效专项（2026-10-08）

本次用户新的截图指出：① 旅人头像交互虽好但照片过小；首页整体红框占比过大；② Navbar 底部蓝色长渐变线突兀；③ 首页、介绍、目录黄色标题舞台几乎没有明显动态。

本轮只改受影响的局部 UI，不触碰路由数据、后台配置、文章/小说内容：

- **旅人照片放大**：不再挤在约 4.2rem 的小头像框，改为独立较大相框（上限约 8.65rem × 7.75rem），保留现有 Hover/Focus 倾斜和抬升反馈，姓名另起一行防止宽度被挤压。

## 9. 分类 / 标签文章列表的局部重排（2026-10-08）

用户在“杂谈”分类截图中框出长标题区，反映左侧标题/元信息挤在一起、右侧箭头大块留白。排查发现原因不是首页 `PostCard.astro`，而是 `src/pages/archive.astro` 内的第二套 `#archive-cards` 筛选结果结构：原卡片使用较大的 `padding-right`、绝对定位的高宽比箭头、旧蓝色竖线和多组前置图标，且遗留同文件的 scoped CSS 与全站 `journey.css` 并存。

**本轮已完成的最小修改：**

- `src/pages/archive.astro`：保留 `#archive-cards`、每个链接的 `data-category` 与 `data-tags`，只替换卡片视觉 DOM 为“日期/分类 — 标题 — 摘要 — 字数/阅读时长/标签 — 窄箭头”；整张卡仍是一条可点击的链接。
- 删除旧卡片专用的整段 scoped CSS，避免大面积绝对定位按钮、渐变底板、竖线和图标与新版持续冲突。
- `src/styles/journey.css`：新建筛选列表网格，主列 `minmax(0,1fr)`、右侧箭头仅 `2rem`，统一信息间距；窄屏进一步缩到 `1.5rem`，无强制向右额外留白。
- 在第一次 Chrome 无头截图中发现 **新 `display:grid` 规则覆盖已有 `.hidden`，导致分类标题为 4 篇但错误展示所有文章**；当场补上 `#archive-cards .journey-filter-card.hidden {display:none}`，重新截屏验证杂谈页只剩其 4 篇（2026暑假有感、来谈谈舍友、白日做梦部与梦想实现部、一些上不了简历但我还挺喜欢的小东西）。此条是重要的 CSS 优先级功能回归防线。

**验证状态**：修订前 `pnpm check` 为 74 files / 0 errors / 0 warnings / 0 hints；`pnpm build` 为 20 页成功、Pagefind 16 页。过滤隐藏优先级修复之后，Chrome 无头浏览器已实际截图确认四篇分类文章正确呈现；最终是否符合亮色主题的审美仍由用户实机复核。
