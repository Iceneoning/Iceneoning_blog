# 冰霜旅途｜UI 组件与页面布局规范

> 状态：SUPERSEDED / 历史 UI 视觉规范；新设计见 [V0.3 透明 UI](../../V0.3_晴空冰晶折射/03_透明UI及全站页面构图规范.md)，原有功能合同仍须保护。
> 依赖：[05 全站总览](./05_冰霜旅途全站视觉重构总览.md)
> 目标：从“均匀毛玻璃三栏博客”调整为“主内容突出、侧区轻量、背景参与叙事”的视觉体系

## 1. 视觉观感与节奏

主图不能再只是被遮住的壁纸；页面应像铺在通透插画前的一张**旅行记录界面**。使用明确的主次和非对称重心，不做重型战术 HUD 或泛滥的圆圈十字线。

三个视觉层级：

| 层级 | 内容 | 材质/对比 |
| --- | --- | --- |
| Primary 主舞台 | 首页主标题、精选文章、文章正文、小说作品内容 | 稳定可读的半透明浅色/深色面板，层级最清楚 |
| Secondary 同行信息 | 个人卡、日期/时间、文章辅助信息 | 更轻、更薄，少量边缘高光 |
| Tertiary 导航工具 | 分类、标签、次要信息、装饰 | 低权重，不以完整大白盒占据注意力 |

原则：不增加等尺寸大卡的数量；背景可以在边缘可见，但内容文字对比度不靠运气。

## 2. 桌面首页：沿用结构，改造视觉

既有结构基于 `MainGridLayout.astro`：上方 Navbar、博客左右侧区、中间 `#swup-container`。**不为视觉改动搬动 Swup 容器或 Sidebar 所在职责层。**

- **Navbar（站点识别区）**：保留现有功能入口。左侧站名/符号形成固定标识；导航下沿可呈现一段轻薄航线与单个“当前站点”信标。当前栏目强调是位置与明度，不靠无限发光。
- **左栏（旅行者信息）**：个人信息仍是第一识别内容，但不再把每个分组都做成同等强的白玻璃方块。头像/名字与一句简短介绍成为稳定锚点；分类、标签适度压缩为轻面板/分隔线。不可减少键盘可操作性。
- **中心内容（内容主舞台）**：首屏优先塑造“启航”或精选内容的标题层次：大标题/小引导语/内容入口清晰区分，构图可略微偏左但不挤压文章。保持现有文章/精选/回顾功能，拒绝为美化制造冗余信息卡。
- **右栏（时间与旅程）**：时间、日历、辅助功能作为沿路的“路标”，配小型信标或路线端点；减少不必要的轮廓层次，不将功能区变成大型仪表盘。
- **留白**：主航线只走卡片缝隙、背景裸露的区域或装饰专用边缘，不能从文字上方穿过，不能让三个卡片视觉上形成“电路板”。

## 3. 可辨识的统一签名

全站仅保留一个显著的签名组合：
`短弧航线（SVG） + 蓝白信标小圆点 + 冰晶细切角`。

应用密度：Navbar 1 处、首页首屏最多 1 处主航线、左右栏各最多 1 处弱化节点。其他文章卡/按钮不复制全套装饰。小面积切角可以只出现于首页视觉焦点，不强行给每张卡切角。

信标在开场结束后停留于导航标识/首页焦点位置；页面切换时的同一个视觉动机可以延续，但不是创建一套“全局跟随鼠标的光球”。

## 4. Design Tokens（建议初稿，须截图调优）

不得写死只适配某一背景的蓝色；从已有 `--primary`、Light/Dark/Hue 主题变量派生。

| Token | 目的 | 初始建议 |
| --- | --- | --- |
| `--journey-accent` | 信标/选中态 | 优先继承 `--primary`，默认视觉意向为晴蓝 |
| `--journey-line` | 静态航线 | 浅色主题约 0.14～0.24 Alpha 的主题蓝 |
| `--journey-glow` | 局部高光 | 冷白 + 晴蓝，集中在 6～20px 小区域 |
| `--surface-primary` | 主内容表面 | 与背景保持充分对比；透明度由截图决定，不预设统一值 |
| `--surface-secondary` | 辅助表面 | 比 Primary 减重，但确保文字可读 |
| `--surface-tertiary` | 弱面板 | 尽量靠留白、排版、分隔线建立层级 |
| `--journey-radius` | 统一圆角 | 在现有 Fuwari 圆角体系内收敛，不另造一套 |

不建议混用 4～5 种模糊强度、强发光描边或大面积玻璃折射。**面板透明度不是越低越高级**：主要通过排版和层级强化通透性。

字体：保留全站现代无衬线 UI；标题层级主要靠字号/字重/行距，而非大面积英文字号或科幻编号。小说正文继续用原衬线栈，不纳入发光字样式。

## 5. UI 组件行为

- Navbar：Hover 可出现细微下沿信标位移；Focus 与选中态必须具备无动画也明确可见的指示。
- 卡片：Hover 只做 1～2px 内的轻高光、微弱阴影改变或轻抬升；不能大幅度整体位移；保留既有 Mouse Edge Light 需避免叠加两套效果。
- 按钮/链接：统一明确的 Hover/Focus；按钮的交互反馈比光迹装饰优先。
- 文章封面：不要整齐地全部压成同尺寸空白横条；视觉主次可通过一张更重要的封面/标题确定，但不能改变文章语义和排序。
- 日期时间：时间功能原样保留，可将装饰降噪；不得因为“重新设计 UI”删除信息或改计时逻辑。
- 目录/搜索/标签：低调但可发现；不能以清爽为理由降低触达性。

## 6. 全站页面差异

- **首页**：唯一可以拥有完整“航线 + 信标 + 开场”的强主题页面。
- **归档/文章/关于/朋友屋**：统一色彩材质与局部标记，不重复首页大片航线，更不能让背景运动妨碍文章阅读。
- **小说馆/作品页**：保留作品卡与 Showcase 的数据驱动及独立布局；可以以同套配色和切面更新 Hero 外观，不能让装饰遮挡立绘。
- **小说阅读页**：单列、宽外壳、正文约 46～50rem，移除长时间运行的背景粒子；底部感应阅读工具栏与键盘 Focus 交互保持。Navbar/背景/主题共享，但博客侧栏不能进入阅读页。

## 7. 响应式约束

- 宽屏（建议从 1280～1440px 验）：三栏可展现，但中心仍是首要焦点。
- 1024～1279px：必须以**主内容真实容器宽度**决定内部排版；不可让左栏出现后压扁封面/中文标题。
- 平板/手机：弱化或隐藏长航线，仅保留一枚简化信标；布局优先单列、按钮可点、阅读卡不贴边；不制造横向滚动。
- 不用固定的屏幕坐标决定线条穿过卡片的位置；位置以容器锚点/留白区域计算。

已有 `docs/V0.1版本修复/HOME_NAVIGATION_LAYOUT_INCIDENT.zh-CN.md` 记录了 1052px 下首页严重压缩事故；这份功能防回归协议仍然有效。

## 8. 可访问性与稳定性

- 正文目标至少满足 WCAG AA 对比度（普通文字 4.5:1，大字 3:1）；暗色主题单独验收。
- `prefers-reduced-motion` 时完整关闭非必要位移/光迹，静态信标仍能表达选中状态。
- 背景/装饰层必须 `pointer-events: none`、`aria-hidden`，不得覆盖焦点或拦截滚动。
- 无 JS/低端设备仍能获取信息、导航和完整内容，不依赖动画来“解锁”页面。
- 禁止因 Hover 状态、路由切换、字体载入造成可见布局跳变。

## 9. 视觉验收

用户应在 **1 秒内**判断“这是一个有旅途航线/信标语言、明亮通透的个人博客”；第一视线落到中心内容，其次是左侧人物信息、右侧时间功能。UI 改版前后功能入口与信息字段保持等价。最终以实屏截图/录像而非样式值验收。
