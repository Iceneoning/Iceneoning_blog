# 冰霜旅途｜开场动画与交互动效规范

> 状态：SUPERSEDED / 旧 Beacon Wake 动效设计不再使用；新动效是否制作须先通过 [V0.3 美术导演审核](../../V0.3_晴空冰晶折射/05_动效导演设计与审美验收.md)。
> 动效名称：Beacon Wake / 信标唤醒
> 关键目标：第一帧是**真实页面**，动画是叠加的识别动作，不是加载屏

## 1. 核心动作

光点沿一条弧形旅途线快速滑过，在路径末端凝聚成小型蓝白信标。此后，信标成为 Navbar / 首页焦点附近的常驻签名，导航和 Hover 只复用同一种轻量语言。

视觉因果为：**航线亮起 → 光点穿行 → 路标微亮 → 信标停驻**。

无需把全文、左右栏或背景先藏起来等光迹“揭幕”。必要的 UI 高光联动可以做，但**实际内容第一帧已存在且可操作**。

## 2. 时间轴（建议起点）

| 时间 | 动作 | 禁止事项 |
| --- | --- | --- |
| 0ms | 原背景、Navbar、左右栏与首页主内容正常呈现；静态航线可见 | 黑屏、空白遮罩、正文初始 opacity:0 |
| 0～160ms | 起点亮起，短段航线产生方向感 | 整屏亮度/对比度突变 |
| 160～680ms | 一枚光点沿 SVG 路径穿行，身后出现少量短寿命光尘 | 粒子铺屏、光束划过正文 |
| 680～950ms | 终点信标轻微扩散后收束，沿途节点依次闪一下 | 独立卡片大面积移动 |
| 950～1100ms | 所有动态装饰平滑退出，仅保留静态信标和航线 | 卡片二次出现/页面跳动 |

总时长建议 0.9～1.1 秒；截图测试后可以压到 0.7 秒，但不能为了“表现完整”把真实内容延迟到动画尾声。

## 3. 页面状态机

```text
INITIAL（DOM 正常渲染）
  ├─ motion reduce / JS 不可用 / 非首页 → STATIC
  ├─ 同一会话已播放 → STATIC
  └─ 首次到达首页且可播放 → PLAYING
                                      ├─ 路由跳转/离屏/资源异常 → CLEANUP → STATIC
                                      └─ 动画完成 → CLEANUP → STATIC
```

静态态：背景、航线与信标都完整存在，但无运行中的 intro requestAnimationFrame。首屏出现不依赖“播放完成”事件。

建议本标签页会话只播放一次（可使用 sessionStorage 或等价会话状态；存储不可用时必须安全降级）；重新进入首页、后退/前进及刷新时不能制造加载等待，也不能重播引起闪烁。播放入口必须由路径和页面状态判断，不应在所有页无差别初始化。

## 4. 路由与 App Shell 合同

已核查的代码：

- `astro.config.mjs` 当前设置 `containers: ["#swup-container"]`；
- `MainGridLayout.astro` 的 Navbar 和普通博客左右侧区在该内容容器外；
- `NovelLayout.astro` 也使用独立布局，Navbar 保持在其 `#swup-container` 外；
- 旧 `home-intro.ts` 和 `home-intro-renderer.ts` 目前是空文件，不能假定旧 WebGL 开场仍在运行。

因此：

1. 对**普通博客页互相切换**，只替换既有中心容器；Navbar、两侧稳定区域不可因动效重新挂载/隐藏/上移。
2. 从普通博客到**小说独立布局**，应服从小说区已定义的布局切换边界；不能为了“全站同一 Shell”强行给小说页加入博客侧栏。
3. 背景/长期装饰实例的生命周期优先挂在既有页面 Shell，而不是每次被替换的正文 DOM。
4. 轻量导航反馈应从现有导航状态推导：一个小信标在可用时做约 150～220ms 的位置/高光过渡；不是模拟加载进度，不等待请求完成才显示内容。
5. 使用 Swup 既有生命周期钩子做清理/重算，避免重复事件监听、重复 Canvas 或导航点击失效。

## 5. 动效分级

**Level 0：静态（强制）**：SVG 航线、信标、卡片分层与无动画选中态必须成立。
**Level 1：交互（第一版）**：开场 1 次光迹，Nav 轻量过渡、卡片微高光、Focus 指示。
**Level 2：环境（第二版可选）**：20～40 颗低密度光尘，离屏/非首页停止，用户肉眼确认不分散注意力才加入。
**Level 3：图形学研究（不在当前实施）**：仅在确有瓶颈、基线通过并单独批准后讨论 Shader；不得因“展示技术实力”提前引入。

## 6. 技术选择与解耦

- **SVG**：Bézier 曲线、点位、信标、沿路径的光迹；建议 `pathLength` 或 Motion Path，仅 1 条核心运动轨迹。
- **CSS**：轻微透明度、局部 Glow、Transform、Hover/Focus，尽量走合成属性，避免触发布局。
- **Canvas 2D（可选）**：光点尾部极少量短命粒子或后续空气光尘；不要让 Canvas 接管 UI。
- **JS**：播放状态、可见性、路由生命周期、异常清理、Reduced Motion；不做逐帧 DOM 布局改写。

禁止为动画添加新的全屏覆盖层，禁止阻止滚动/点击，禁止绑定永久 `pointermove` 重计算全布局，禁止使用 `filter: blur()` 对整张背景聚焦过渡。

## 7. 可访问性与降级

- `prefers-reduced-motion: reduce`：完全跳过移动光点，直接展示静态信标，不做延迟。
- `document.visibilityState` 变为 hidden：暂停/取消动态，恢复页面时不重新播放完整开场。
- SVG/Canvas 出错、浏览器不支持特性、低端移动端：退化为“原背景 + 静态航线/信标”。
- 光迹和光尘全程 `aria-hidden`、`pointer-events: none`；不制造频闪，不污染 Focus Ring。
- 首页 Hero 与主体文字始终具备足够对比度，动画不能覆盖正文、头像眼部或重要按钮。
- 禁止依赖自动播放音效；第一版不使用声音。

## 8. 反例与禁止回归

- V0.1 “全屏失焦 + 正文 1450ms 后出现”：像延长 Loading；
- V0.2 “WebGL 全屏光束 + 180/96 粒子 + 3200ms 总时长”：成本与视觉风险过高；
- “全屏黑屏后 Shader 偶尔闪一帧”：不得再出现；
- 正文与 Navbar 突然向上抬起、两侧重排、背景闪烁：不得再出现。

旧实验记录仍可阅读，但其参数和文件职责**不是当前实施合同**。

## 9. 验收路径

直接 URL 首次打开首页、刷新首页、首页站内返回、普通文章互切、首页→小说馆→阅读页、缩放和浏览器后退、禁用 JS、Reduced Motion、移动端分别核对：

- 用户无需等待 Intro 即可读标题并点击导航；
- 只有一次完整光迹，之后只保留静态签名；
- 切页无双层 Canvas/重复监听；
- 没有黑屏、灰蒙蒙、闪屏或因动画引起的布局跳变；
- 页面不可见后停止运行，异常能清理；
- 失效时静态网站保持完整功能。
