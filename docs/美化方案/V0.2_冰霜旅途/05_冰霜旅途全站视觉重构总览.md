# 冰霜旅途｜全站视觉重构总览

> 状态：CURRENT / 现行设计基线（2026-10-08）
> 类型：设计决策与实施入口；**本文不是已实现声明**
> 范围：全站视觉语言、博客 UI、背景、首页开场与交互动效
> 执行者：Astar（后续实施）；本轮仅编写文档，不修改代码
> 取代：V0.1_历史视觉实验 目录中的 01～04 旧视觉方案、`docs/开场动画/晨光聚焦开场动画设计.md`，以及小说区旧视觉规范中与全站新风格冲突的部分

## 1. 一句话设计

**晴空通透的插画背景 + 一条穿行在留白中的旅途航线 + 一个被“点亮”的蓝白信标。**

记忆点是“一笔光迹经过、信标停留”，而不是全屏雾、复杂 Shader 或大量发光卡片。
站点视觉代号：**冰霜旅途 / Frostbound Journey**；关键词：晴空、航线、冰晶切面、光尘、旅程。

## 2. 为什么重构

依据当前首页截图与已有实验记录，现有画面层级偏均匀：背景像淡化壁纸，Navbar、左栏、正文卡、右栏普遍使用接近的玻璃白盒，没有单一视觉锚点。原有 Fog 与 Depth Map 实验进一步证明，改写整张插画的颜色或几何会破坏人物肤色、高光和形体。
本次将**背景叙事、UI 信息层级、动画行为**做成一个系统，但不重写信息架构。

## 3. 已拍板的设计决策（Decision Log）

| 编号 | 决策 | 不允许回退到 |
| --- | --- | --- |
| D-01 | 背景原画优先，保留原始通透、轻量单层 Pointer Parallax | 变灰、全屏雾/遮罩、Depth Map 扭曲 |
| D-02 | 背景辨识度来自“航线、信标、少量冰晶结构”，图层与内容解耦 | 全屏网格 HUD、随意铺满图标 |
| D-03 | UI 重建主次节奏：主内容鲜明、工具区轻、小说阅读安静 | 所有区域都是同权重白色玻璃卡 |
| D-04 | 开场是“已存在页面的视觉唤醒”，不是加载器 | 黑屏、先隐藏正文再长时间淡入 |
| D-05 | 首页完整动效一次；站内切页只做轻量局部信标反馈 | 每次切页重播完整片头 |
| D-06 | 除必要局部效果外，第一版只用 CSS/SVG/Canvas 2D | 全屏 WebGL、Three.js/PixiJS、GPU Raymarch |
| D-07 | 普通博客的 Navbar / 侧栏行为与 Swup 局部替换合同优先于美化 | 顺手换路由、重挂载 Shell 或扩大刷新范围 |
| D-08 | 小说区保留独立无侧栏阅读布局、目录和阅读控制交互 | 统一三栏模板导致小说正文变窄 |

## 4. 规范优先级与适用范围

1. 交互与功能合同：现有源代码与未废弃的功能技术文档（含小说区结构、配置、阅读行为）。
2. 本套现行视觉设计（05～09）。
3. V0.1_历史视觉实验 目录中的 01～04、旧开场文档及旧小说“视觉”规范：仅作为历史实验记录，不再指导新美术实现。
4. 冲突处理：**功能合同优先保留；视觉实现选择本套规范；不能靠猜测改功能**。

这意味着“标记旧视觉文档过时”**并不等于**所有小说功能文档、事故复盘、性能文档也过时。不能把旧文档中真实的现状描述自动当成新设计要求，也不能因废弃旧外观而删除其功能。

## 6. 正式范围（第一轮）

- 首页：Navbar 标识、首页核心内容的视线起点、卡片材质层级、左右工具区减重。
- 全站：基础 token、阴影/边框/交互反馈、静态背景与局部航线符号统一。
- 开场：进入首页的一次性装饰光迹；正常内容首帧可用；无需独立 Loading Screen。
- 小说馆/作品页：复用统一视觉 token，但保留已有 Showcase 数据驱动、内容结构。
- 小说阅读页：优先可读性，不在正文周围插入动态航线或粒子。

## 7. 非目标

本设计阶段不新增栏目、不改变文章数据结构、不换部署方案、不重做搜索/归档功能、不改变小说路由/阅读进度协议、不重写 Fuwari 与 Swup 基座、不因视觉需求引入依赖、更不要求立即实现 WebGL 特效。

## 8. 审核门槛

**任何“工程验收通过”均不能替代截图和交互审美复核。**
Astar 必须先出静态设计效果，对照 1440px / 1052px / 390px 与 Light/Dark 截图；静态合格后再加动效。达不到“背景清澈、UI 有层级、首页有记忆点”三项时，不进入下一阶段。
