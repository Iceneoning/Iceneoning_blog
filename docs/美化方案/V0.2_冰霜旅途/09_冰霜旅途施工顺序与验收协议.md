## 2. 施工阶段（小步、独立回滚）

| 阶段 | 最小施工范围 | 完成门槛 |
| --- | --- | --- |
| S0 基线截图与审计 | 不改 UI；核对 DOM / CSS / Swup / 主题 / 资源；定 1440/1052/390 截图 | 现状、风险和实际改动目标明确 |
| S1 静态 UI 层次 | Design Token、Navbar 标识、主/辅/弱卡分层、左右栏轻量化 | 文字可读、全部原功能入口保留、无布局回归 |
| S2 静态背景签名 | 1 条主航线、3～5 节点、1 个 Beacon、少量冰晶边角 | 无动态时仍有记忆点；不压暗原画、不压正文 |
| S3 开场动效 | 单次 0.9～1.1s SVG 光迹、信标收束、状态机和降级 | 首帧完整、无等待、切页无重播 |
| S4 可选环境微动 | 只有在 S1～S3 审美和性能通过后，加入有限 Canvas 2D 光尘 | 不抢主体注意力，不带来持续显著 GPU 压力 |
| S5 页面统一与收尾 | 归档、文章、关于、朋友屋、小说馆、作品页适配；阅读页保守 | 全站同一语言，小说阅读依旧安静、可读 |

每阶段分别提交可审查 Diff；不要将“改布局 + 改背景 + 新 Shader + 旧代码清理”混为一个巨大 PR。

## 3. 具体工程保护线

1. **Swup**：保留 `#swup-container`，普通博客页面 Shell 区域不随中心内容刷新；不得挪动 Navbar/左右侧栏以满足动画。
2. **小说区**：独立布局和单列阅读不改，阅读正文宽度约 46～50rem；Showcase 的 Frontmatter、目录、阅读进度和底部工具栏交互不丢。
3. **背景**：原 WebP 图片与配置优先保留；禁止再带回 Fog / Depth Map / 全屏 WebGL。
4. **代码规模**：仅添加明确职责的轻量样式/小模块；发现旧空文件时先审计引用，再决定是否需要复用，不为保持历史结构而写两套 Intro。
5. **主题**：每个新 token 同时验证亮色、暗色、Hue 切换，不在路径切换后断开响应。
6. **事件生命周期**：独立初始化、销毁、Resize、可见性清理；一个视觉语义只存在一个实例。
7. **回滚**：每阶段应能单独关闭新视觉层，回到原始背景与功能；不依赖删改业务逻辑恢复。

## 4. 视觉验收矩阵

| 视口/条件 | 必查项目 |
| --- | --- |
| 桌面 1440 × 900（Light） | 视觉锚点、航线完整、中心内容主次、人物肤色与亮部不变灰 |
| 桌面 1440 × 900（Dark） | 对比度、信标不过曝、面板不过于压暗背景 |
| 桌面 1052 × 900 | 首页精选/回顾不发生中文逐字竖排、侧栏出现后主内容不被压扁 |
| 手机 390 × 844 | 无横向滚动、无覆盖按钮、无重型航线、内容可读 |
| 宽屏 1920 × 1080 | 航线不随视口拉长成巨大斜线，构图不过空 |
| Reduced Motion | UI 全部直接可用，动线静止但信标保留 |
| JS 故障 / SVG 失败 | 原背景、文章与导航完整可用 |
| 路由切换/后退/刷新 | 没有黑屏/跳动/重复监听/双 Canvas |

如新增视觉跨多个主题，还应在用户现用 Hue/调色板方案中补一轮截图。

## 6. 性能与测试

优先静态 CSS/SVG；仅在必要时使用单个低密度 Canvas 2D，不能引入全屏常驻渲染器。测试要关注实际 FPS、CPU/GPU 占用、主线程长任务、页面跳动、资源体积与实际截图；历史 Shader 的高成本预算不沿用。

建议运行仓库现有的 `pnpm check` / `pnpm build`（以 `package.json` 当前脚本为准）和有针对性的实际浏览器验收。**构建成功只证明工程在相应条件下通过，不证明视觉达标。** 禁用动画后还应验证功能完整。

本轮**未运行**构建、浏览器测试或实现改动；此处都是 Astar 后续施工验收合同。
