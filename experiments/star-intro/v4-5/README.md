# V4.5「星水涟漪」· 独立美术精修

本次在 V4.4「繁星共鸣」上只增加轻微的水感，不改变已经确认的繁星密度、波前触发数量、中心标题位置和星幕撕裂转场。**正式博客不接入，V1～V4.4 不修改**。

## 预览方式

双击 `H:/vs_code/fuwari/experiments/star-intro/v4-5/index.html`。

默认水感 40%。可以把「水感」滑块依次调整为 0%、40%、70%、100%，判断哪一档最适合。这一条滑块和原来的「强度」滑块独立；关闭「星纹」也会关闭附加的水感光效。

## 新增的 Shader 美术机制

- **微弱 UV 折射**：在主波和回声波附近，对 JS 星空 `sampler2D` 的采样 UV 沿径向做小幅位移。位移由两道不同时相的正弦振荡和局部高斯包络共同控制，并非全屏水面扭曲。低强度时仅让背景星点轻微流动。
- **柔和波前光晕**：为断续的星光波前附加一层低透明度、较宽但不刺眼的光带，让观众感受到“涟漪”传播方向。
- **细微焦散亮度变化**：沿波前角度周期缓慢改变亮度，增加一点“水”的呼吸感，而不恢复早期粗大的平滑光环。
- **星芒优先**：原来的 58×34 GLSL 星点候选网格，以及 560 远景、220 中景、42 近景、260 星尘、110 星芒等 JS 分层全部保留。
- **不修改揭晓镜头**：原有噪声驱动的逐像素星幕撕裂（空间揭晓博客 MP4）和其亮边逻辑完全保留。

## 性能与安全边界

新增的是单次 Shader 采样 UV 轻微位移和局部程序化亮度计算；仍在 WebGL1 单次 Fragment Pass 内渲染。不增加视频像素读取、外部资源、纹理层数或跨帧拷贝。Canvas 源纹理仍隔帧上传，最大约 125 万像素。

WebGL 不可用继续走 JS Canvas2D 降级；用户开启系统「减少动态效果」时跳过动画；不接入生产 Astro / Swup / 背景视频生命周期。待本人审美确认后方可讨论正式接入。

## 本轮浏览器实测

- Windows Edge 无头实例正常编译、运行 WebGL，原博客 MP4 视频 `readyState=4`；`node --check` 通过。
- 在**同一帧约 51.9% 进度暂停**，分别将「水感」调到 0%、40%、100% 并即时重绘，三张截图视觉确有差异：40% 只加入轻柔涟漪和折射，100% 更接近可见的水波光弧。Slider 更改期间进度保持不变，未捕获 JavaScript 运行异常。
- 已检查正常播放的星纹中段、撕裂揭晓和终帧；开场白位置未动，裂隙揭晓仍在。
- 自动化交互验证：暂停进度冻结、继续后前进、星纹开关、跳过、重播均正常；此为独立 Chrome 内核浏览器的单机原型测试，非生产性能或跨设备验收。
- 视觉推荐先观察默认 40%，然后尝试 70%；这是可调试的审美参数，并未确定正式上线强度。

## 验收重点

1. 默认 40% 水感与 0% 的差别是否**可感知但不过分**。
2. 水感不应把星点“融化”，不能使标题区域模糊或让四周星团变脏。
3. 涟漪仍是“繁星被唤醒”，而不是一整圈水纹。
4. 3.6 秒左右的空间撕裂及最终少女背景是否保持无断层、无突兀切换。
5. 重播、暂停、跳过、Shader 开关、强度与水感滑块均应可用，浏览器没有 Shader 编译错误。
