## 技术结构

```text
原背景 MP4 / 海报（始终可见）
  ├─ 透明 Canvas2D（115 个 JS 星点）
  ├─ 透明 WebGL1（GLSL 光带/星轨/涟漪）
  └─ DOM 文案（沿用 V1 top:42%;left:50% 居中定位）

进场约 3.3 秒：Shader 增强、粒子亮起、标题显现
结束后：Shader 不移除，而是切到低强度 Ambient Phase
```

- WebGL1 的光线由 **Fragment Shader 真正逐像素计算**，不是 CSS 发光边框。
- 以原 16:9 背景中的两处纵向光丝（近 x=0.28、0.65）和右侧弧线为锚点，按 CSS `object-fit: cover` 换算对应屏幕坐标。
- Video 按 `min-width:901px`、细指针与正常动态偏好加载；若不可播放则由原静态海报回退。移动端则采用博客保存的 `mobile-background.jpg`，并关闭依赖桌面背景坐标的 Shader 与粒子动画，避免光带错位。
- 不进行视频帧纹理采样，因此当前 Shader 只实现**叠加光效**，不是真正修改视频像素或对人物进行像素级识别、跟踪。
- 目前的光束位置基于**静态海报**近似设定，若 MP4 的光带大幅移动，动态位置仍需视觉验收并考虑关键帧轨迹映射。

## 渲染与生命周期

- WebGL 和 JS 粒子都保持透底，**没有 V2 的纯紫色不透明渐变背景**。
- 开场默认约 60 FPS 的 rAF 目标节奏；3.3 秒后以约 24 FPS 更新常驻装饰；实际帧率取决于浏览器及设备。
- Canvas 总像素约不高于 205 万，设备像素比桌面不高于 1.2，移动端不高于 1。
- 页面进入后台时暂停 rAF；重返时恢复且不按离开时长快进；播放控制可单独暂停动画。
- WebGL 失败时显示状态文字并退化为 JS 星尘；对系统 `prefers-reduced-motion` 偏好直接展示静态画面。
- 不进行外部请求、安装依赖、服务端渲染或修改项目的背景资产。

## 验收建议

1. 比较播放开场时的 0%、115%、200% Shader 强度。
2. 开启「只看 Shader」，确认光束流动、星轨与波纹的位置及动态变化。
3. 动画结束后等待 10–20 秒，确认常驻背景持续微动且未重新变成紫色幕布。
4. 检查少女是否受到遮挡，播放/跳过/重播与浏览器缩放是否稳定。
